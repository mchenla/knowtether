# KPDM 产品需求文档

## 1. 产品定义与本轮目标

KPDM（Knowledge Product Development Meta-Model，知识产品开发元模型）是一套由人主导、AI Agent 主动辅助的原创知识开发框架。它帮助创作者从问题、经验、材料和思想出发，发展可说明的知识贡献，形成框架、书籍、文章、报告或系列成果，并通过检查、实际使用和反馈持续修订。

人的主导权贯穿问题选择、思想发展、价值取舍、核心主张和最终表达。Agent 可以研究、提议、质疑、起草和核验，在明确授权内连续工作。框架同时支持不使用 Agent 的创作。

本轮产品目标是：让创作者能从一个真实任务直接开始，知道自己需要作出什么判断、可以委托什么、怎样判断成果是否达到预期；让必要记录支持创作、检查与后续接手，且工作量随任务复杂度变化。

对于尚未形成中心思想的任务，KPDM 还应帮助作者发现值得追问的问题、比较解释并建立理解。用户可以先探索再形成主张，也可以带着明确意图直接委托起草；两种入口均可在必要时返回研究。

KPDM 的交付形态包括规范、使用指南、可裁剪模板、实例、质量检查方法及机器可读模型。当前产品不以独立软件为交付前提。

### 文档效力

本 PRD 将现有规范与 0.5 候选方案整理为下一轮产品需求。需求中的“必须”用于拟议版本的设计和验收，不表示对应能力已经实现或验证。

当前作品基线仍为 `0.4.0 trial / conditional-pass`；`0.5.0-rc.1` 是项目内候选包。本文件不替代元模型宪法，不批准候选发布，不关闭历史开放项。文档版本与框架版本分别管理。编号使用 `KPDM-PRODUCT-REQ-01`，避免与既有版权、引用、数据与来源协议 `KPDM-PRD-01` 混淆。

## 2. 上下文与问题判断

KPDM 从 CBBOK 开发实践提取而来，逐步形成 27 个对象、四种工作模式、阶段检查、模板与机器模型。后续以 Core-6 重新组织创作内核，并明确质量约束与生产控制的不同职责。9 月候选包进一步提出人主导的创作入口、报告 Profile 和一张合并工作单。

产品问题集中在如何把这些能力转化为实际创作支持。

| 问题 | 现有材料中的依据 | 对产品的要求 |
|---|---|---|
| 初次使用可能被流程和字段压住 | 初始化协议列出十二步和十三类必备文件；短文虽能合并，仍要求保留字段 | 提供可直接开始的入口，说明何时需要展开记录 |
| 人机分工容易停留在批准和签字 | 0.5 候选专门补充人在思想发展、选择和表达中的职责 | 把人的创作判断和 Agent 的主动工作写进实际流程 |
| 结构齐全不能证明成果有用 | 质量约束明确区分生产状态与验证状态；跨主题效度仍开放 | 将读者任务、真实使用和失败处置纳入验收 |
| 不同成果需要不同工作强度 | 既有 Profile 已允许文章合并记录，复杂框架加强治理 | 同一创作内核下提供可解释的裁剪规则 |
| 人读规范与机器配置存在漂移 | O-01、O-02 涉及四层成果关系及机器模型映射；候选处理尚未迁入权威源 | 明确版本关系，并逐项检查规范、模板与机器表达 |
| 轻量性尚未得到实际确认 | 候选短文只有结构检查与 Agent 审阅，O-09 仍待真实作者反馈 | 用真实创作观察记录负担，不能以字段少直接判为易用 |

这些是文档事实及其产品分析。尚未开展的访谈、采用情况、节省时间和效果提升不作为已有结论。

### 2.1 STORM／Co-STORM 带来的设计修订

STORM 把资料研究与提纲准备放在长文生成之前，以多角度提问和基于检索材料的追问改善研究。其研究也发现来源偏见传递、把互不相关事实错误连接等问题。该结果来自百科式写作任务，不能直接作为 KPDM 原创框架或书籍的效度依据。[STORM 论文，§3、§6](https://arxiv.org/html/2402.14207v2)

Co-STORM 允许用户旁听或介入讨论，以动态知识图帮助跟踪，并让主持角色从未使用材料中提出新问题。论文的消融实验提示主持作用值得关注；真人反馈也指出明确目标下可能需要更简洁的回答。因此 KPDM 应按任务选择探索强度，不能默认增加角色和讨论轮次。[Co-STORM 论文，§3、§5.4、§6.2](https://arxiv.org/html/2408.15232v2)

| KPDM 当前缺口 | 本轮吸收的设计 | 在 KPDM 中的取舍 |
|---|---|---|
| “研究、比较、质疑”停留在职责描述 | 把问题发现、材料查证与追问写成可执行路径 | 研究可独立交付；开放探索不要求预先填好中心主张 |
| 用户需要主动想出大部分问题 | 增加按材料发现遗漏的提问职责 | 用具体问题和来源说明价值，禁止制造专家共识 |
| 长会话难以形成共同理解 | 提供持续更新的知识概览 | 最小实现为可编辑提纲或表格；图形界面按需扩展 |
| 有引用容易被误认为论证成立 | 加强主张与原文对应、来源冲突和推理跨度检查 | 分别检查事实、推论和原创选择 |
| 只看最终稿，难判断方法价值 | 同时评价研究过程、作者理解与最终成果 | 增设比较试验，单独记录增加的成本 |

以上是 KPDM 对外部方法的适配提案。三层结构、Core-6、四种工作模式和 27 个对象保持既有职责，不因借鉴增加同级模型；本轮交付仍是框架规范与使用材料，不要求部署 STORM 或建设多 Agent 软件。

## 3. 用户与核心任务

### 3.1 用户角色

| 角色 | 需要完成的任务 | 本轮支持重点 |
|---|---|---|
| 原创知识创作者 | 把问题、经验或思想发展成可表达、可使用的成果 | 首要用户；以当前作者的实际任务试用 |
| 合作作者、编辑或评审者 | 理解作者意图、发现问题、接手修订或核验 | 能从必要材料判断当前版本、依据及未决事项 |
| 框架维护者 | 从不同项目中提炼可复用规则，管理规范和版本 | 区分项目特例与通用规则，维护一致性 |
| AI Agent | 在授权内研究、构思、生产和检查 | 执行协作角色；需要明确输入、任务、限制和返回条件 |

独立作者、小型协作团队等更广泛用户的适用性属于待验证假设。当前不据此承诺组织级部署能力。

### 3.2 必须支持的场景

| 场景 | 用户起点 | 预期结果 |
|---|---|---|
| 从零发展思想 | 一个问题、一段经验或不完整想法 | 明确受众与目的，比较候选解释，选择值得发展的主张 |
| 先探索再决定写什么 | 对主题有兴趣，但不知道还应问什么 | 获得与目标相关的问题、已知内容、分歧和知识缺口；可停在研究成果，无须生成文章 |
| 发展文章或报告 | 已有中心思想，需要研究和表达 | 获得与意图一致的稿件，清楚其依据、限制和待核验处 |
| 建设框架或书籍 | 多个相关概念、材料或章节 | 形成知识结构与表达结构，减少定义冲突和论证重复 |
| 接手已有成果 | 一份旧稿、旧框架或部分完成的材料 | 判断哪些可保留、哪些缺少依据、哪些需要重构，无须全部重建 |
| 人机持续协作 | 任务跨多轮会话或多个参与者 | 新参与者理解有效版本和授权，发现旧上下文产生的偏差 |
| 检查与修订 | 草稿已形成，或收到实际使用反馈 | 找到问题、修订相关内容，并确认修改没有引入新的冲突 |

成果读者与框架使用者需要分别验证：作者能使用 KPDM，不代表其作品已对读者有用；作品被读者理解，也不自动证明 KPDM 降低了创作成本。

## 4. 产品范围与设计取舍

### 4.1 适用范围

覆盖以提升理解、判断、学习、行动或创造能力为目的的知识创作。框架／知识体系、书籍、文章、报告、系列成果为平等的产品类型。教科书、课程、手册和配套工具依据读者任务组合适配。

原创贡献可以体现为新问题、新解释、新方法或有价值的综合；必须说明与已有认识的关系。产品不要求每项成果发明全新理论。

本轮优先验证文章与报告的轻量入口，并继续用框架或书籍检查复杂任务。这是验证顺序，不是成果类型的重要性排序。

### 4.2 本轮不纳入

- 纯文学、纯艺术的专用创作规范；保留扩展可能，不设计空置的复杂接口。
- 通用项目管理、个人知识库、资料收藏系统和编辑器的完整替代。
- 自动认定事实为真、自动授予原创性或权威地位。
- 无人承担判断与发布责任的全自动知识发布。
- SaaS 平台、账号权限、支付、协作后台或特定厂商集成。
- 《知识产品工程》的整书改写；该书拥有独立作品身份与生命周期。

### 4.3 核心取舍

1. 先让用户完成创作任务，再按需解释对象与协议；使用者不必先学完 27 个对象。
2. Core-6 是功能覆盖，不强制创作按六步顺序推进；研究、试写和反向检查可以往返。
3. 短任务合并记录，复杂任务拆分和版本化；任何必填项都应说明它支持的判断或风险控制。
4. 真实性、权利、安全与人的责任持续适用；轻量化主要减少重复填写和不必要的独立文件。
5. 机器检查负责可机械判断的结构与一致性；事实判断、可理解性和有效性采用相应来源核验与真人验证。
6. 研究的覆盖面服从读者任务；明确目标的短任务可直接推进，开放问题才展开多角度探索。角色与讨论轮次增加须有实际收益。
7. 知识概览是现有对象的使用视图，服务于理解与取舍；它不会因排成树状或图形而成为经验证的知识结构。

## 5. 产品结构

| 层次 | 产品职责 | 用户得到什么 |
|---|---|---|
| 创作内核 Core-6 | 覆盖目的、知识内核、依据、可用化、表达、验证与演进 | 六个可直接回答的问题，帮助发现思想和成果中的缺口 |
| 共同质量约束 | 真实性、可理解性、概念克制、权利安全隐私、认知诚实、可追溯性 | 适用于各种成果的检查要求及失败处理 |
| 协作与生产支持 | 任务、上下文、来源、决定、检查、版本和发布管理 | 按任务需要启用的工作单、协议与记录 |

规范关系沿用现有裁决：《KPDM 三层元模型》是唯一元模型宪法，《KPDM 元模型》提供下位对象词汇。

0.5 候选提出将“四层成果”解释为产物视图，并将 StatusClaim 表示为 Claim 子类型。这两项作为本 PRD 的拟议实现方案沿用，分别保留 D024、D025 的待裁决身份。实现时必须同步规范和机器表达；若最终裁决不同，调整映射，不增加竞争性的解释入口。

## 6. 使用流程与人机分工

用户可以用自然语言交代任务。框架应帮助整理已知信息，并仅就影响下一步工作的缺项返回讨论。

| 活动 | 人的职责 | Agent 可执行的工作 | 最小保留结果 |
|---|---|---|---|
| 明确意图 | 选择问题、受众、预期变化和投入范围 | 梳理材料、指出歧义、提出任务建议 | 意图、成果类型、用途、质量目标 |
| 发展思想 | 提出经验和判断，选择追问方向及候选思想 | 从材料提出问题、查证、比较解释、追问遗漏与反例 | 研究问题、暂定主张或明确缺项、依据及人的选择 |
| 组织成果 | 修正知识概览，决定论证方向和表达重点 | 组织已知内容与分歧，修订提纲、试写、发现知识缺口 | 知识概览、表达方案、来源位置与未决问题 |
| 起草与修订 | 处理实质取舍、修正重要表达 | 在授权内连续起草、改写和检查 | 稿件、重要修改及待决问题 |
| 检查与接受 | 判断内容和风险，接受具体版本 | 核对来源、反向审阅、机械检查 | 预设条件、检查结果、失败处置、接受版本 |
| 使用与演进 | 提供实际反馈，决定修订和发布 | 分析问题、定位影响、协助修订 | 使用结果、修改范围、复核与版本记录 |

新核心主张、作者原意变化、适用范围实质扩大、未授权风险及关键检查失败必须返回人处理。普通措辞、格式和已授权的材料整理可持续执行。Agent 的提议应明确保留为提议，人的接受记录应对应具体版本。

沿用 Explore、Architect、Produce、Verify 四种模式和 G0–G7；本表是使用入口，不新增一套并列生命周期。内部探索允许保留暂定主张，进入正式生产和发布前执行相应用途的条件。

### 6.1 按意图选择研究方式

**目标明确时**，利用已有主张、材料与结构推进，只补足会影响成果的缺项。**问题开放时**，先形成研究问题和暂定知识概览；用户可以观察进展、加入材料、否决方向或要求收敛。探索、聚焦和收敛是 Explore／Architect 内的工作选择，不新增生命周期阶段。

一次研究循环包括：

1. 根据用户目的、已有材料或相邻主题，提出不同角度的问题，并说明为什么相关。
2. 查找允许使用的材料，保留原文位置；区分资料所述、作者推断及尚无回答的问题。
3. 根据新材料追问冲突、条件或遗漏。Agent 应主动说明新增问题可能改变什么判断。
4. 更新知识概览与问题状态，由人随时修正重点。记录关键选择，不要求用户逐轮批准。
5. 到达任务覆盖目标、用户要求收敛、预定预算耗尽，或连续两轮没有新增相关信息时停止当前探索。最后一种为本 PRD 的可调默认值，不是通用定律；未解决问题保留。

研究可以交付问题清单、带来源的概览和待决选择。只有需要表达为作品时，才据此组织文章、章节或报告；结构须能随发现修订，不能先用目录限制所有研究。

### 6.2 知识概览与材料记录

知识概览优先用普通提纲或表格表示：问题／概念、当前回答或分歧、相关来源、未决项、作者选择。每个条目可回到对应资料和当前版本。用户修改某项解释或取舍后，相关提纲与稿件应标出影响位置。

它复用 Architecture、Concept、Claim、Evidence、Source、UncertaintyItem 和 Decision 等对象。问题可以作为 Problem 的分解或工作包的研究项；研究摘要可纳入 ContextPack。短任务仍可用一张工作单承载，不另设强制独立文件。

材料允许来自公开网页、经授权的本地文档及作者提供的记录。资料的检索入口可以替换，但应保留材料标识、版本或获取时间、支持段落／页码／章节、对应问题及使用限制。只取得搜索摘要时标明未核对原文，不登记为已完成事实核验。实现参考 STORM 的材料对象及研究／提纲／文章接口；上述定位精度和权利记录是 KPDM 的适配要求。[STORM 接口实现](https://github.com/stanford-oval/storm/blob/main/knowledge_storm/interface.py)

### 6.3 示例：由探索转入原创判断

以下为验收情境设计，不是真实案例结果。作者准备写“怎样安排团队复盘”，起初只给出主题和目标读者。Agent 提议分别研究复盘目标、参与者负担与后续行动，根据材料发现“频率”可能不是唯一变量，再提出是否应区分不同工作类型。作者可否决不相关分支，选择一个待验证的解释。随后工作转为聚焦论证；该解释仍标为作者假设，不能因为有若干来源就写成已成立事实。若作者只想了解问题，则直接交付研究概览。

## 7. 功能需求与验收条件

优先级：P0 为本轮产品验收必需，P1 为核心路径后续扩展，P2 为储备。下列条件为需求目标，执行结果另行登记。

| 编号 | 优先级 | 需求 | 验收条件 |
|---|---|---|---|
| R01 | P0 | 提供从自然语言任务开始的使用入口 | 使用者无需阅读对象表即可形成首项任务；问题、受众、预期交付、用途、质量目标与下一步均可识别；可选研究交付，不要求已有中心主张；未知项明确保留 |
| R02 | P0 | 支持 Core-6 的完整覆盖与往返创作 | 对一件成果能定位六项回答或未决项；知识与依据可互相修订；不以写完六段说明代替实际成果 |
| R03 | P0 | 明确人的主导权与 Agent 授权 | 在新主张、原意变化、普通措辞调整三个测试场景中正确处理返回与继续执行；未接受提议不写成作者立场 |
| R04 | P0 | 提供一张工作单的轻量入口 | 单一主旨、低依赖任务可用一份合并记录完成协作；无强制重复抄写；既有硬性字段可直接填写或定位到引用位置 |
| R05 | P0 | 根据风险与依赖增加控制 | 含来源冲突、权利不明或多成果依赖的案例触发相应核验和记录；说明新增工作的理由，不仅按字数判断 |
| R06 | P0 | 支持成果类型适配 | 每个平等 Profile 均给出目的、结构重心、控制裁剪、质量目标与读者任务；报告包含问题、分析、判断和建议之间的关系 |
| R07 | P0 | 维护主张与依据的联系 | 核心主张可区分事实、解释、建议或原创构造；外部事实定位到可复核材料片段，推理与原创选择另有说明；识别“来源存在但不支持结论”、跨来源错误关联及来源冲突；缺失信息不自动补成事实 |
| R08 | P0 | 支持跨会话与协作接手 | 接手者能查到有效输入版本、当前主张、委托范围、未决事项和验收条件；过期上下文案例被识别并重新核对 |
| R09 | P0 | 将验证对准读者任务 | 实质生产前声明至少一项读者任务；检查结果能说明是否完成及失败原因；不得用 AI 模拟反馈填入真实读者结果 |
| R10 | P0 | 区分生产、验证和发布状态 | 草稿写完、结构检查通过、作者接受、独立复核和发布批准分别可识别；缺少发布条件时无法据此登记发布通过 |
| R11 | P0 | 管理唯一权威源与变更影响 | 修改一个核心定义后，能找出受影响章节、文章或工具，并记录同步或待修订状态；派生视图不提高源状态 |
| R12 | P0 | 对齐规范、模板与机器表达 | 存在需求到文件／字段／检查的映射；执行标准 Schema 正例与负例；能分别报告结构错误、语义漂移和未验证效度 |
| R13 | P0 | 支持已有成果的增量接入 | 用一份已有草稿识别缺失项并生成修订任务；保留原有可用内容与来源，不要求从零重填全部模板 |
| R14 | P1 | 将项目反馈转化为框架改进 | 反馈区分作品缺陷和方法缺陷；通用规则升级附异质项目记录、改善依据、反例与回退条件 |
| R15 | P1 | 提供面向不同读者的表达指导 | 示例用读者熟悉的语言说明责任、来源和进入条件；目标读者能够复述，不以替换词表机械判定合格 |
| R16 | P2 | 扩展专用工具或其他创作类型 | 仅在真实需求与现有能力缺口明确后立项；复用现有模型前先验证适用性 |
| R17 | P0 | 支持开放研究与多角度追问 | 在材料不足的真实任务中给出相关问题及选择理由；根据后续材料产生追问、修订或明确无新增发现；允许以研究概览结束，不强制写成作品 |
| R18 | P0 | 支持用户随时调整研究方向与停止 | 用户可补充、纠正、缩小范围、暂停或要求收敛；下一项工作响应最新要求，保留已完成材料与未知；预算耗尽不记作研究已充分 |
| R19 | P0 | 维护人可修正的知识概览 | 能定位主题、当前回答、分歧、来源和待决项；加入相冲突材料后更新相关条目；用户修正后可识别受影响结构，不产生第二份权威内核 |
| R20 | P1 | 按任务需要发现讨论遗漏 | 在预设“检索到相关材料但尚未讨论”的场景中提出与用户目标有关的新问题并标注材料位置；重复或无关扩展可关闭；该职责可由单 Agent 承担 |
| R21 | P0 | 支持研究中间成果交接与恢复 | 普通文档可交接问题、材料、概览、版本与停止位置；仅修订提纲时复用仍有效的研究材料，上游变更时定位需重查部分；自动化实现另需记录模型、检索设置及可取得的用量信息 |
| R22 | P1 | 提供可独立试用与贡献的示例包 | 非设计者能从任务输入、材料、关键选择、稿件及检查结果复现方法步骤；反馈可关联具体版本与失败位置；公开前单独确定许可和清理私有依赖 |

R17–R21 参考 STORM／Co-STORM 的研究与协作机制后形成；R22 是 KPDM 自身的试用交付要求。R20 的独立职责启用与 R22 完整示例包列为后续扩展，基础主动提问已由 R17 覆盖。各项要求约束方法的可执行性，不承诺本轮提供自动化运行器、图形界面或多个运行中的 Agent。

### 7.1 轻量工作单

沿用候选版八项设计，但不把八项提升为不可变原则。

| 项目 | 用户需要留下的内容 |
|---|---|
| 意图 | 为谁、解决什么、形成什么成果、内部或公开用途及 Q 目标 |
| 中心思想 | 当前主张、拟议贡献及尚未决定的问题；探索任务可填写研究问题与“主张未定” |
| 表达结构 | 研究任务填写或引用暂定知识概览；作品任务填写读者如何理解成果，允许引用稿件结构 |
| 依据与适用范围 | 来源及支持位置、推理、冲突、反例、未知，以及权利和敏感信息状态 |
| 委托范围 | 人与 Agent 各自负责什么；输入版本、探索范围与预算／停止条件、何时返回人判断 |
| 验收条件 | 读者任务、必要核验、通过条件及核验责任 |
| 结果与修订 | 实际检查、失败项、修改和仍开放的问题 |
| 人的决定 | 接受或退回的内容版本、实质取舍及独立的发布决定 |

前六项在草拟前形成足够支持当前任务的信息；后两项随检查更新。已有文件可被引用，填写“不适用”时说明原因。短文场景中的 1000 字上限和三个分论点来自既有试验，不作为所有文章的产品规则。

研究交付只需与研究任务相适应的前六项信息；允许结构和主张暂定，不以空缺为由强迫作者过早作结论。新增研究信息沿用这八项容纳，避免为一次小任务再加一套表格。

现有初始化协议的必要信息如何进入上述八项，必须制作字段映射；尚未修改的规范继续适用。若确需删除强制字段，须同步修订对应规范，不能通过新模板静默取消。

### 7.2 增加控制的触发条件

| 触发情况 | 增加的必要支持 |
|---|---|
| 数据、强因果判断或高影响建议 | 逐项来源核对、适当领域复核、明确未知与风险处置 |
| 权利不明或敏感材料 | 来源与使用条件记录；在问题解决前限制相应使用 |
| 多章节、多成果或多人依赖 | 版本化上下文、明确任务分工、权威矩阵与变更影响记录 |
| 核心定义或方法变化 | 记录决定、识别受影响成果、重做相关检查 |
| 公开发布 | 至少 Q3，并完成对应独立检查与真实读者测试 |

增加控制不要求自动复制整套模板。每项新增记录应对应一个需要被发现或被处理的实际问题。

## 8. 质量与体验要求

1. **读得懂。** 快速入口和实例先用普通语言说明动作，再引入术语；用户能说出下一步做什么及为什么。
2. **负担可测。** 区分创作、研究、必要核验与纯记录维护所用时间，保留返工原因；不将必要研究成本算成表格负担。
3. **如实表达。** 缺失来源、未决思想、作者未接受、未进行真人验证均显式保留；禁止推定通过。
4. **可迁移。** 核心工作可用普通文档完成，机器模型为可选支持；不得依赖特定会话、平台或厂商才能解释成果。
5. **可维护。** 同一规范有唯一权威来源；示例、模板和机器模型标明适用版本，旧材料保留迁移方式。
6. **可恢复。** 上游改变或检查失败后，能够指出需重做的部分、保留可用成果，并记录新版本。
7. **交付清楚。** 成果面向读者的表达与内部生产记录分开；仅保留使用者正确理解和使用所需的状态及限制。
8. **探索可控。** 目标明确时优先简洁、直接的支持；用户可看到新增发现、未解决问题及下一步选择。知识概览应减轻接手成本，其有效性需实际观察。
9. **成本可比较。** 研究预算与结果分别记录；自动化时按可获取信息报告耗时、调用或 token 用量。更换工具或恢复会话后记录有效配置，不将默认配置静默当作原配置。

Q0–Q4 继续沿用现有质量体系。质量目标、实际检查结论和允许用途分别记录；Q4 仍是权威候选，不是外部权威认定。

### 9.2 本轮拟议验收方案

以下样本数量与门槛是本 PRD 新提出的试用标准，尚未执行；应在试验开始前确定，不得看到结果后下调以取得通过。

| 验证 | 样本与方法 | 通过条件 |
|---|---|---|
| V01 首次使用与记录负担 | 当前作者及至少 2 位未参与框架设计的创作者，各完成 1 项低依赖真实任务；记录耗时与求助位置 | 3 人均能仅凭入口与实例形成首项任务；首次工作单目标不超过 15 分钟；任何关键缺项或无法继续的问题均需修订重测 |
| V02 主导权与主动辅助 | 分别测试新主张、原意变化、普通修改；观察作者如何接受或否决 | 对应 R03 的处理正确；没有擅自代替作者作实质决定，也没有要求逐句批准 |
| V03 异质项目 | 至少 2 个性质不同、非 KPDM 自举项目；至少包含 2 种 Profile，其中 1 项为多单元成果 | 各项目按预设条件完成真实任务，留下问题、返工与限制；有合并记录及展开控制的实际材料 |
| V04 读者可用性 | 每个验证项目至少 2 位目标读者执行预设理解、判断或使用任务 | 按任务事先设定的评分规则通过；关键意义或适用条件被误解时修订并复测，不能用平均满意度抵消 |
| V05 接手与变更 | 1 次新会话／新协作者接手，1 次上游定义修改，1 次旧草稿接入 | R08、R11、R13 均有可查结果；过期内容与需重做部分被识别 |
| V06 一致性与失败测试 | 检查发布范围内规范、模板、机器模型及正反例 | P0 需求均有对应检查；无未处理的权威冲突；缺来源、缺接受、旧版本等负例能被对应机制发现 |
| V07 探索价值与额外成本 | 至少 2 个非 KPDM 主题，各设置目标相近、难度相当的成对任务；比较原工作方式与新增研究路径；对调先后顺序，尽量保持材料权限和预算一致 | 预先定义相关性、关键问题覆盖、解释深度、有效新发现、耗时与记录负担；执行完整比较并记录负面结果。只有观察到预设收益且关键质量未下降时，才支持在该场景推荐扩展探索；否则调整或限用 |
| V08 人的控制与知识概览 | 测试开放主题和明确短任务，分别加入纠正、缩小范围、停止指令及一次来源冲突；让真实使用者从概览找依据与未决项 | R18、R19 的动作与定位全部正确；明确短任务不强迫展开研究；使用者能说清当前选择与未知；主观轻松程度与任务结果分别记录 |
| V09 引用与论证反例 | 准备“有链接无支持”“同源转载伪装多来源”“两事实被误连成因果”“只取得搜索摘要”“作者假设误写为事实”各 1 例 | 各例均被识别或明确留作未核验，不得被登记为已支持的事实；保留定位、处置与复核结果。模拟材料只用于机制测试 |
| V10 中间成果复用 | 研究交付后暂停；由另一会话或协作者仅调整结构，再引入一项会改变主张的新材料 | 已有问题与支持材料可接手；前一操作不重复完整研究，后一操作识别并重查受影响部分；记录配置变化与实际成本，恢复成功不等同于结果完全可复现 |

小样本用于发现可用性问题和支持有限试用结论。效率改善须结合任务复杂度、原工作方式及返工记录判断；本轮不承诺固定百分比提升。记录维护时间占比、作者重复使用意愿和返工次数先作为观察指标，不伪造现有基线。

V07–V10 是本次新增验证提案：分别对应 R17、R18–R19、R07 和 R21，并配合 V01–V06 覆盖全部 P0。启用 R20 时在 V07 中增设“有／无专门遗漏检查”的比较，判断额外角色是否有贡献；R22 用非设计者接手示例包单独验收。作者理解、研究过程、最终稿与实际读者任务分开评价；不以引用数量、Agent 数量或语言模型评分代替这些结果。不得直接采用 STORM／Co-STORM 的偏好比例作为 KPDM 的达标率。

### 9.3 阻断条件

下列任一情况出现时，对应成果或候选版本不得登记为通过：

- 未接受的新核心主张被写为作者立场。
- 事实、引用、真人反馈或批准记录被虚构。
- 公开成果缺少相应 Q3 检查，或目标读者不能完成关键任务。
- 人读规范、模板与机器配置对同一核心规则给出冲突指令。
- 记录形式变轻，却丢失了必要来源、风险、责任或接受信息。
- 用户要求停止或缩小范围后继续扩展，或把预算耗尽写成知识问题已经解决。
- 引用可访问但不支持主张，或资料间的推测关系被当作已核实事实。

## 11. 风险、假设与待决定项

| 项目 | 当前判断 | 处理方式 |
|---|---|---|
| 八项工作单是否足够轻 | 候选设计，缺少作者体验 | 用 V01 观察实际填写与接手；允许合并、引用或调整字段 |
| 更广泛创作者是否需要这套框架 | 待验证需求假设 | 观察未参与设计者是否能完成任务及愿意再次使用 |
| 跨类型通用性 | 有 Profile 设计，缺少足够异质验证 | V03 保留每种类型的任务与失败记录，限制外推 |
| 自动检查的覆盖 | 可查结构与部分一致性 | 将来源核验、真人任务和外部效度分开报告 |
| 使用成本压过收益 | 初始化与治理要求可能带来负担 | 记录每项控制发现的问题和维护成本；无价值重复项进入修订 |
| 现行文档与候选并存 | 0.5 尚未替换权威基线 | 显示适用版本与迁移差异，禁止只改入口版本造成假同步 |
| 新试用门槛是否合适 | 15 分钟及样本数为本 PRD 提案 | 试验前确定；若调整，保留理由并对后续试验生效 |
| 多角度研究带来范围膨胀 | 新增机制可能提高成本或偏离明确任务 | 设置停止条件，以 V07 比较收益，以 V08 检查用户控制 |
| 百科式整理压过原创思想 | 外部方法的任务与 KPDM 不同 | 保留作者经验、推理、价值选择和原创构造的身份；只对需要外部依据的事实要求对应引用 |
| 知识图使未核验信息显得确定 | 组织形式不能证明关系成立 | 概览展示分歧与未知，关系变更回到材料和作者选择 |
| 模拟角色被当成独立专家 | 多个角色可能共享同一模型和来源 | 明示模拟身份；分离真实读者、领域复核与 Agent 反向检查 |
