# KPDM 质量约束

本文件定义横跨 [KPDM 三层元模型](KPDM%20%E4%B8%89%E5%B1%82%E5%85%83%E6%A8%A1%E5%9E%8B.md) Core-6 的质量约束。它们不是新增元对象，而是所有知识对象、表达视图与生产活动必须接受的检查。0.5.0-rc.2 未改变六项约束的实质内容，只更新版本身份与指针：状态主张的字段表达见 [KPDM 元模型](KPDM%20%E5%85%83%E6%A8%A1%E5%9E%8B.md) 的 Claim `status` 子类型；发布前逐项检查见 [发布前合规与完整性检查](../03%20Quality%20and%20Governance/%E5%8F%91%E5%B8%83%E5%89%8D%E5%90%88%E8%A7%84%E4%B8%8E%E5%AE%8C%E6%95%B4%E6%80%A7%E6%A3%80%E6%9F%A5.md)；读者任务验证方法见 [质量高度与验收等级](../03%20Quality%20and%20Governance/%E8%B4%A8%E9%87%8F%E9%AB%98%E5%BA%A6%E4%B8%8E%E9%AA%8C%E6%94%B6%E7%AD%89%E7%BA%A7.md)。

## 六项约束

| 约束 | 最低要求 | 主要失败模式 |
|---|---|---|
| 真实性 | 事实、数据、引用、推断和未知被如实区分 | 幻觉、假引用、把假设包装为事实 |
| 人类可理解性 | 目标读者能复述意义与边界，并完成预设任务 | 生涩冰冷、结构完整但无法理解或使用 |
| 概念克制 | 只有确有表达缺口时才创造术语 | 故弄玄虚、术语堆砌、换名冒充原创 |
| 权利、安全与隐私 | 来源、许可、署名、保密和敏感数据满足条件 | 有引用无许可、泄密、隐私风险 |
| 认知诚实 | 评价只随标准和证据变化，不随作者期待变化 | 迎合、溜须拍马、以赞美替代判断 |
| 可追溯性 | 主张、来源、决定、修改和重要 AI 贡献可追踪 | 静默漂移、无法复核或还原创作过程 |

## 人类可理解性

人类可理解性不是“文风必须活泼”，而是目标读者能够建立正确意义。严谨、技术性或简洁的文风都可以通过；术语很多却无法复述和使用的文本不能通过。

最低检查：

1. 读者能用自己的话复述中心主张；
2. 读者能说清关键边界、限制以及事实与推断的区别；
3. 抽象内容有必要的解释、例子、反例、情境或可观察结果；
4. 读者能完成预先声明的理解、判断、学习、行动或创造任务；
5. 文风符合 Profile 和使用场景，而非套用统一的“AI 文风”。

等级规则：Q0–Q2 为改进项；任何 Q3/Q4 的公开知识产品为硬门。未通过时不得发布为 pass。


## 模型语言指纹与文字温度

人机协作创作必须识别并消除大模型偏好的语言指纹。这里的“指纹”不是对技术水印的推断，而是指某些模型反复生成、在人类自然写作中密度较低的用词、句式和概念组合。成品不得因为这些习惯而显得生硬、疏离、故作深刻或像机器说明书。

“锁”“情境”“边界”“证据”“循证”“纪律”“铁律”等词不是禁词。它们只有在含义准确、读者熟悉且没有更自然的表达时才保留。以下情况必须改写：

1. 同一抽象词在相邻段落高频重复，成为组织句子的万能支架；
2. 原本可以直接说明的人、事、责任、资料和行动，被改写成抽象模型语言；
3. 为追求整齐、权威感或“方法论感”而自造概念、缩写、层级和成组术语；
4. 连续使用抽象名词、口号式对仗、机械排比或“不是……而是……”句式，却没有增加信息；
5. 用“闭环、底座、抓手、赋能、范式、颗粒度、链路、认知升级”等流行表达替代可观察的动作和结果；
6. 文字读起来像控制台提示、模型说明或审查清单，不像专业人士在向具体读者解释问题。
7. 标点上的模型偏好：用长破折号（"—"“——”）代替逗号、冒号或短横线来连接前后文，或用它做数字区间与并列的分隔。中文正文只在真正的插入语或转折处用破折号；数字区间、并列、副题一律用短横线" - "（前后各一个空格）或冒号、顿号。

改写优先级：

- “锁”根据实际含义改为确定、固定、限制变更、停止调整或获得批准；
- “情境”优先改为场景、情况下、实际工作中或具体事件；
- “边界”优先说明适用范围、职责分工、包含什么和不包含什么；
- “证据”根据来源改为数据、记录、文件、访谈、观察结果或事实；
- “循证”优先写明依据哪些数据、记录或研究；
- “纪律”“铁律”优先改为规则、要求、约定、做法或必须满足的条件；
- 自造概念优先还原为目标读者已经使用的专业术语和自然语言。
- 长破折号“—”“——”优先改为" - "、冒号、逗号或顿号；只有确属插入语或语气转折时才保留，且一篇之内不超过个位数。

文字温度不等于煽情、口语化或降低专业性。合格表达应当：

- 先说清具体的人、问题、行动和后果，再引入必要的抽象概念；
- 让读者感到作者理解实际工作的压力、限制和取舍；
- 使用自然、有节奏的句子，避免每段都采用同一种模板；
- 以尊重和平等的口吻解释，而不是训诫、炫技或制造权威感；
- 保持准确、克制和专业，同时能够顺畅朗读并被目标读者自然复述。

检查方法：

1. 统计高频抽象词和模型偏好词，检查其是否集中出现；
2. 将每个抽象词替换为具体对象、动作或来源，比较信息是否更清楚；
3. 朗读正文，标记机械排比、固定句式、突兀术语和缺少人称主体的句子；
4. 由熟悉该领域但未参与创作的人标记“像 AI 写的”“冰冷”“故弄玄虚”或“不像业内人士会说的话”的位置；
5. 对保留的自造术语逐项执行新术语准入检查。

Q0–Q2 将语言指纹作为改进项；Q3–Q4 若存在成片模型语言、无必要的自造概念或明显影响理解与信任的冰冷表达，语言质量 Gate 直接 fail。

## 新术语准入

每个候选新术语必须回答：

1. 现有术语为何不足；
2. 新词的定义、边界和非例是什么；
3. 它与现有概念是什么关系；
4. 不使用它会损失什么解释力或可用性；
5. 如何用目标读者熟悉的自然语言解释。

无法回答时，不创建新术语。品牌需要、视觉整齐和制造原创感均不是充分理由。

## 认知诚实与反迎合

AI 与人工协作者不得因作者身份、投入程度、偏好或期待而提高评价。以下词语一旦作为评价使用，必须附判据、证据、适用范围和限制：完成、完整、写透、创新、成熟、有效、可靠、可用、拿来即用、经过验证、标准、权威、中立、领先、国际化、世界级、最佳。

Verify 至少检查：

- 最强反例和替代解释；
- 是否把篇幅、结构、术语数量或任务完成率误当作有效性；
- 是否省略作者不愿看到的缺陷；
- 是否把“值得探索”改写为“已经成立”；
- 是否存在貌似专业但无法翻译为普通语言的空洞表达。

礼貌可以保留，判断标准不得因此降低。
## 状态主张与不得自证完成

完成度、成熟度、有效性、可靠性、可用性和权威性都是主张。它们不能因为作者宣布、文件状态字段改名、清单勾选、版本号提升或生成任务结束而成立。

每项状态主张必须能够回答：

1. 对象：什么成果或对象达到该状态；
2. 范围：覆盖哪些部分、场景和人群，不覆盖什么；
3. 判据：达到该状态必须满足哪些预先声明的条件；
4. 证据：哪些记录、测试或使用结果支持结论；
5. 验证者：作者自检、同行复核、独立复核还是外部验证；
6. 版本：结论适用于哪个版本和时间点；
7. 限制：哪些未知、反例和外推限制仍然存在。

最低检查：

- 状态词不得比其证据覆盖范围更宽；
- 生产状态与质量状态必须分开，例如 `drafted` 不等于 `validated`；
- 内部一致性检查不得改写为真实场景有效性；
- 虚拟案例、自举测试和作者自评不得改写为独立验证；
- 派生视图不得提高权威源的状态或省略其限制；
- Q3–Q4 公开产品的高影响状态主张必须经过独立复核，不能由同一作者或同一生产智能体既产出又判定通过。

无法满足上述条件时，使用事实描述。例如不写“内容已经写透”，而写“已为 94 个对象提供规定字段，并通过 ID、名称和引用一致性检查；可复现性与真实场景效度尚未验证”。

## 成品表达与元话语隔离

生产状态必须记录在控制层，不得自动进入成品表达层。公开知识产品正文只保留读者完成理解、判断、学习或行动所必需的内容：事实、主张、证据、边界、规则、责任、状态、生效条件和使用指令。

下列内容默认属于生产控制信息，不得进入 Q3–Q4 成品正文、封面、页眉、标题、副标题、演示页或面向使用者的工具界面：

- “候选发布版”“内部探讨参考”“供某人审阅”等工作流标签；
- “本文件不宣称……”“我们认为……”“作者尝试……”等对作品自身的辩护、评价或创作旁白；
- 思考过程、生成过程、任务完成说明、会话信息、资料库路径和未授权框架名称；
- 面向编辑者的检查清单、修改理由、提示语和发布前自检记录；
- 以“不得自证”方式解释创作伦理，而没有转写为对对象、证据、验证者和生效条件的直接规则。

允许保留的例外只有三类：

1. 法律、许可、保密或监管要求必须公开的披露；
2. 读者正确使用产品所必需的版本、适用范围、生效状态和限制；
3. 教学目标明确要求展示推理过程，且已与结论和规范文本分区。

转写规则：

- 不写“本文件不证明机制有效”，写“有效性认定需要真实运行记录、结果反馈、基线比较和独立复核”；
- 不写“候选发布版”，在控制台账记录 `publication-candidate`；成品只显示必要的版本号和生效状态；
- 不写“本轮不讨论长期组织”，写“长期组织依据事项队列、投入、利益冲突和结果证据另行决策”；
- 不写“不得由作者自证完成”，写“提出者、批准者和有效性复核者不得由同一责任主体同时承担”。

Q3–Q4 产品若出现无法证明读者价值的元话语，Release Gate 直接 fail。内部文件是否保留工作流标签，由 Profile 明确；一旦文件承担正式沟通或决策功能，同样适用本规则。
