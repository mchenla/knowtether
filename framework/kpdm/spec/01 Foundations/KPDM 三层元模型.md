# KPDM 三层元模型

> 权威地位：本文件是 KPDM 唯一的元模型宪法，规定知识产品创作的第一性结构、所有实例继承的原则与发布红线。
> [KPDM 元模型](KPDM%20%E5%85%83%E6%A8%A1%E5%9E%8B.md) 是其下位的对象模型，提供实现词汇、字段、状态与关系，不定义第一性结构。

> 权威裁决见 KPDM-D018（未随公开包分发）；本次合并为 KPDM-D026 拟议事项，待作者接受。

## 定位与人的主导权

KPDM（Knowledge Product Development Meta-Model，知识产品开发元模型）是一套由人主导、AI Agent 主动辅助的原创知识开发框架。它帮助创作者从问题、经验、材料和思想出发，发展可说明的知识贡献，形成框架、书籍、文章、报告或系列成果，并通过检查、实际使用和反馈持续修订。它不规定某一领域应该相信什么，而是规定如何把问题转化为可理解、可依据、可使用、可验证并可演进的知识产品。

人决定创作目的、受众、核心思想、价值取舍、接受的原创贡献和最终表达，对风险与发布承担责任。人可以授权 Agent 持续执行范围清楚的研究、起草和检查，不必逐句指挥。

Agent 可以提出问题、查找材料、提供候选想法、比较解释、提出异议、推演反例、草拟和整理。候选想法不因由 Agent 提出而失去价值，也不因写得流畅而自动成为作者的立场。涉及新核心主张、作者原意变化、适用范围实质扩大、未授权风险或关键检查失败时，返回人处理。

作者的接受要对应具体成果版本。普通措辞、格式和已授权的材料整理可以持续执行；未经人接受的草稿保留草稿身份。原创指可说明的独立贡献，可以是新问题、新解释、新方法或有价值的综合，不要求每件成果发明全新理论，但必须说明与已有认识的关系。

对于尚未形成中心思想的任务，KPDM 还帮助作者发现值得追问的问题、比较解释并建立理解。人可以先探索再形成主张，也可以带着明确意图直接委托起草；两种入口都可以在必要时返回研究。研究的覆盖面服从读者任务：目标明确的短任务直接推进，开放问题才展开多角度探索；增加角色或讨论轮次必须有实际收益。

框架同时支持不使用 Agent 的创作：去掉 Agent 一列，其余规则不变。

## 适用范围

当前适用范围是以提升认知、判断、学习、行动或创造能力为目的的知识创作。框架或知识体系、书籍、文章、报告、系列成果是平等的产品类型；教科书、课程、手册和配套工具依据读者任务组合适配。知识型叙事属于适用范围；纯文学与纯艺术创作暂不纳入，因为其主要价值可能是审美、情感、象征和多义体验，不宜被强制套入主张与依据的验证模型。文学艺术只保留可替换创作目的、成果结构和评价方法的接口，尚未实现对应规范。

## 第一层｜Core-6 创作内核

| 内核 | 创作者需要回答 | 最小结果 |
|---|---|---|
| 目的 Purpose | 为谁解决什么认知、判断、学习、行动或创造问题？希望读者发生什么变化？ | 受众、场景、问题、范围、预期变化 |
| 知识内核 Knowledge | 我究竟提出什么？和已有认识相比贡献在哪里？ | 概念、主张、模型、关系、原则 |
| 依据 Grounding | 为什么可信？在哪些条件下不成立？ | 来源、证据、推理、反例、限制、未知 |
| 可用化 Enablement | 读者怎样据此理解、判断、学习、行动或继续创造？ | 方法、解释、示例、练习、工具、判断依据 |
| 表达 Expression | 怎样组织为适合人阅读、学习、查询或执行的形式？ | 叙事、章节、条目、图表、案例、索引或界面 |
| 验证与演进 Validation & Evolution | 哪些已经检查，哪些仍待检验？如何据此修正？ | 核验、使用结果、反馈、版本、修订和限制 |

### Core-6 的完整链

`目的 → 知识内核 ↔ 依据 → 可用化 → 表达 → 验证与演进 → 修订知识内核或其表达`

六项是功能覆盖，不是强制的六个连续步骤。研究、试写和反向检查可以往返；短文可以用很少内容覆盖六项，复杂框架可以拆成相互依赖的任务。研究过程中形成的知识概览是现有对象的使用视图，服务于理解与取舍；它不会因为排成树状或图形而成为经验证的知识结构。一个具体对象可以支持多项内核，但其主职责和权威来源必须明确。

### 可用化原则

可用化是把知识内核转化为目标受众可完成的理解、判断、学习、行动或创造任务。它不是要求所有知识产品都提供操作步骤，而是要求项目预先声明希望受众获得何种可观察能力。

验证必须回到该能力：不只检查文本是否写完，还要检查目标受众能否正确复述、区分、迁移、判断、查询、执行或创造。不同 Profile 选择不同任务与证据，不以同一操作性标准强迫所有作品。

## 产物视图｜四层成果

创作过程用 Core-6 描述；创作出来的东西用四层产物描述。两者回答不同问题，不是并列的两套内核。

| 产物层 | 产物 | 核心问题 | 对应的 Core-6 |
|---|---|---|---|
| 知识内核 | 概念、主张、模型、方法、证据 | 知识本身是否成立 | 知识内核、依据 |
| 使用系统 | 工具、模板、流程、评估与决策规则 | 是否能被使用和复现 | 可用化 |
| 表达产品 | 知识体系、书、出版物、文章、报告 | 如何适配读者和媒介 | 表达 |
| 演进系统 | 版本、反馈、案例、研究与治理 | 如何持续变得更可靠 | 验证与演进 |

目的贯穿四层：每一层产物都要能回答它为谁、解决什么问题。

> 本节落实 KPDM-D024 的拟议裁决（四层成果为产物视图，Core-6 为创作功能），用于解除原《KPDM 总纲》「四层成果」与 Core-6 的并列冲突（KPDM-D022）。该裁决仍为 proposed-author-review；作者接受本版即关闭。

## 第二层｜Quality Constraints 质量约束

质量约束横跨 Core-6，不构成新的内容章节或元对象。细则、检查方法与失败处理见 [KPDM 质量约束](KPDM%20%E8%B4%A8%E9%87%8F%E7%BA%A6%E6%9D%9F.md)。

| 约束 | 核心要求 |
|---|---|
| 真实性 | 事实、数据、引用和推断如实，未知不伪装为已知 |
| 人类可理解性 | 目标读者能建立意义、复述核心主张与边界，并完成预期任务 |
| 概念克制 | 不以换名冒充原创；新术语必须证明必要性并提供定义、非例和自然语言解释 |
| 权利、安全与隐私 | 来源、许可、署名、保密和敏感信息满足使用与发布条件 |
| 认知诚实 | 不因作者偏好、投入、身份或期待而提高评价；不以赞美替代判断 |
| 可追溯性 | 核心主张、来源、裁决、变更和重要 AI 贡献能够追踪 |

三条硬性规则在此重申，细则见质量约束文件：

- 人类可理解性：Q0–Q2 作为改进项记录；Q3–Q4 的公开知识产品属于硬门，目标读者不能复述核心意义和边界、或不能完成预设任务时，不得通过 Release Gate。
- 新术语准入：新增术语必须回答现有术语为何不足、新词定义和边界、非例、不使用会损失什么、目标读者如何用自然语言理解；答不出就用普通语言或既有术语。
- 状态主张：「完成、完整、成熟、有效、可靠、可用、经过验证、权威、世界级」等词用于描述成果状态时都是待验证的主张，至少说明评价对象、适用范围、通过判据、支持证据、验证主体、适用版本和已知限制。作者自检、文件齐全、篇幅增加、任务完成或 AI 自评只能证明相应生产活动发生。Q3–Q4 的高影响状态主张必须有独立于主要作者或生产 Agent 的复核，否则标为 provisional、self-assessed 或 unverified。

## 第三层｜Production Controls 生产控制

生产控制用于提高可靠性和协作确定性，不是知识创作内核本身。实例按 Profile、Q 级、风险和依赖裁剪强度：单一主旨、低依赖的任务用一张工作单；触发条件命中时按需展开。细则见 [KPDM 生产控制层](../02%20Methods%20and%20Protocols/KPDM%20%E7%94%9F%E4%BA%A7%E6%8E%A7%E5%88%B6%E5%B1%82.md)。

- 项目与上下文：Project、ContextPack、WorkPacket，轻量形式为八项工作单；
- 质量与未知：QualityTarget、QualitySLO、UncertaintyItem；
- 论证与权威：ClaimGraph、ProvenanceRecord、RightsRecord、DataReference、AIContribution；
- 检查与发布：Validation、RegressionTest、GoldenCase、ReleaseCandidate；
- 治理与演进：Decision、版本、反馈和修订；
- 执行机制：Explore、Architect、Produce、Verify 四种模式，G0–G7 与阶段内 PDCA。

控制强度可以裁剪，真实性、权利、安全、人的最终责任以及 Q3/Q4 的人类可理解性硬门不得裁掉。

## 原则

### 十二条普适原则

每一个实例继承下列原则。项目 Profile 可以加严，不能删除。

#### U1｜真实优先

不得为了论点、品牌、叙事或进度扭曲事实。未知就是未知，推断必须标为推断，预测必须写出前提。

#### U2｜问题与受众先行

项目必须先说明解决什么问题、服务谁、希望发生什么变化。没有读者任务的内容积累不算知识产品开发。资料数量不是进度。

#### U3｜质量高度预设

实例化时必须选择 Q0–Q4 质量目标。外部发布最低 Q3；知识体系、正式著作和希望形成长期权威的产品默认 Q4 候选。

#### U4｜对象先于表达

先稳定概念、主张、证据、方法和关系，再组织章节、文章、演讲或网站。章节是表达视图，不是知识本体；表达视图不能静默改变知识内核。

#### U5｜主张与证据匹配

重要主张标明性质：定义、事实、解释、规范选择、方法规则、预测、原创构造或边界声明。不同主张需要不同校验。没有来源的外部事实和数据不得进入正式发布。

#### U6｜原创与来源并存

原创贡献必须可说明；使用他人思想、表达、图表、数据、代码或结构时必须记录来源、权利状态和使用方式。二次加工不自动免除归属或许可要求。

#### U7｜引用与许可分离

引用解决可追溯和信用问题，许可解决是否有权复制、改编、传播或商业使用的问题。引用完整不代表使用合法；取得许可也不代表可以不署名。

#### U8｜人对目标、判断和发布负责

AI 可以辅助研究、结构、反例、检查和草拟，但作者对问题选择、主张、证据接受、版权判断、风险接受和最终发布负责。

#### U9｜生产与校验分离

作者和 AI 的自检不能成为唯一 Check。阶段门必须有独立视角、机器检查、读者测试或现实验证中的至少一种；高质量外部发布至少需要独立事实与引用检查和独立编辑或读者视角。

#### U10｜可追溯与可复现

核心定义、主张、数据、变换、决策、版本和 AI 贡献必须能追到来源和修改记录。关键数字要能复算。

#### U11｜隐私、安全与保密

不得把未获授权的个人信息、客户数据、商业秘密、受限材料或敏感提示输入外部工具。公开、内部、机密、受限四级必须在初始化时标注。

#### U12｜边界、失败与修正公开

说明适用范围、反例、未知、失败模式和变更。发现错误时保留修正记录，不静默抹除。

### 两条补充条款

原《KPDM 总纲》P1–P7 中与上述原则重复的条款不再单列（对应关系见 [KPDM 0.5 需求映射与迁移](../08%20Evolution/KPDM%200.5%20%E9%9C%80%E6%B1%82%E6%98%A0%E5%B0%84%E4%B8%8E%E8%BF%81%E7%A7%BB.md)）。下列两条没有对应的普适原则，作为补充条款保留：

- **权威来源唯一**（原 P4）：同一核心对象只能有一个权威定义源。书稿、文章、图表和工具都是视图，不得各自重定义；派生视图只能继承或降低权威源的状态，不能升级。
- **内部完成与外部声誉分离**（原 P6）：内部可以交付「出版候选版」或「验证候选框架」，不能自行宣布「权威」或「世界级」。声誉来自同行评审、采用、案例和时间。

### 七条发布红线

出现任何一项即停止发布：

1. 核心事实或数据无可追溯来源；
2. 引用不存在、无法打开或未核实原文；
3. 复制、翻译、改编、图表或图片的权利状态不明；
4. AI 生成的事实、引文或数据未经人工核验；
5. 机密、个人或客户信息未经授权披露；
6. 标题、摘要或营销承诺明显超过正文证据；
7. 作者、贡献者、资助、利益冲突或重大 AI 使用被故意隐瞒。

### 继承规则

每个项目的章程或工作单必须写明：继承版本、加严条款、例外申请和批准人。普适底线没有项目级静默例外。

## 完成定义与不做

一个知识产品只有同时通过内容正确性、结构一致性、证据充分性、读者可用性和出版质量检查，才能关闭。文字写完只代表 Do 完成；草稿写完、结构检查通过、作者接受、独立复核和发布批准是五个分别可识别的状态，见 [KPDM 生产控制层](../02%20Methods%20and%20Protocols/KPDM%20%E7%94%9F%E4%BA%A7%E6%8E%A7%E5%88%B6%E5%B1%82.md)。

不做：

- 不把文件数量、字数或任务勾选率当成果质量；
- 不为显得原创而隐藏理论来源；
- 不先造品牌、认证或「官方」称谓，再补验证；
- 不把一个项目的特殊做法直接升级成普遍规律；
- 不让 AI 生成量替代作者的判断、责任和主张选择。

## Profile

框架或知识体系、书籍、文章、报告、系列成果五种 Profile 地位平等，改变 Core-6 的深度、顺序、形式和控制强度，不删除 Core-6。某项可以非常轻量，但不能成为未作说明的空白。各 Profile 的目的、结构重心、控制裁剪、质量目标与读者任务见 [知识产品类型适配](../02%20Methods%20and%20Protocols/%E7%9F%A5%E8%AF%86%E4%BA%A7%E5%93%81%E7%B1%BB%E5%9E%8B%E9%80%82%E9%85%8D.md)。
