# 上下文包与工作包协议

任何框架、书籍、文章、报告或系列成果在进入实质起草前，先按本协议留下足够支持当前任务的记录。记录有两条路径：**轻量入口**用一张工作单；**展开路径**在触发条件命中时按需增加 ContextPack、WorkPacket 和各类台账。两条路径共用同一套字段含义，展开只是把工作单里的项拆成独立、版本化的对象。

自 0.5.0-rc.2 起，原《实例化初始化协议》（KPDM-INIT-01）并入本文件；协议编号保留。原十二步改写为展开时的检查项，原十三类必备文件改为按触发条件启用。

## 轻量入口：一张工作单

适用条件：单一主旨、适用范围清楚、协作依赖少的任务，例如一篇文章、一份内部报告、一个章节的修订。

| 项目 | 用户需要留下的内容 | 何时形成 |
|---|---|---|
| 意图 | 为谁、解决什么、形成什么成果、内部或公开用途、Q 目标 | 草拟前 |
| 中心思想 | 当前主张、拟议贡献及尚未决定的问题；探索任务可填写研究问题与「主张未定」 | 草拟前 |
| 表达结构 | 作品任务填写读者如何理解这件成果，允许引用稿件结构；研究任务填写或引用暂定知识概览 | 草拟前 |
| 依据与适用范围 | 来源及支持位置、推理、冲突、反例、未知，以及权利和敏感信息状态 | 草拟前 |
| 委托范围 | 人与 Agent 各自负责什么；输入版本；探索范围与预算或停止条件；何时返回人判断 | 草拟前 |
| 验收条件 | 读者任务、必要核验、通过条件及核验责任 | 草拟前 |
| 结果与修订 | 实际检查、失败项、修改和仍开放的问题 | 随检查更新 |
| 人的决定 | 接受或退回的内容版本、实质取舍及独立的发布决定 | 随检查更新 |

规则：

- 前六项在草拟前形成足够支持当前任务的信息即可，不要求填满；后两项随检查更新；
- 已有文件可以引用，不重复抄写；填「不适用」时说明原因；
- 缺失的信息明确保留为未知，不由 Agent 补成事实；
- 八项是本版的可用性设计，不是知识创作的普遍定律；短文试验中的字数与分论点上限只约束该试验；
- 触发 [KPDM 生产控制层](KPDM%20%E7%94%9F%E4%BA%A7%E6%8E%A7%E5%88%B6%E5%B1%82.md)「增加控制的触发条件」中任一情形时，转入展开路径，已填内容不重填。

研究交付只需与研究任务相适应的前六项信息；允许结构和主张暂定，不以空缺为由强迫作者过早作结论。

模板：[轻量工作单模板](../04%20Templates/%E8%BD%BB%E9%87%8F%E5%B7%A5%E4%BD%9C%E5%8D%95%E6%A8%A1%E6%9D%BF.md)。

## 研究任务与知识概览

问题开放的任务先做研究，研究循环见 [人机协作协议](%E4%BA%BA%E6%9C%BA%E5%8D%8F%E4%BD%9C%E5%8D%8F%E8%AE%AE.md)「按意图选择研究方式」。研究的中间成果用普通文档记录，不另设强制独立文件：

- 知识概览：用提纲或表格表示，每条包含问题或概念、当前回答或分歧、相关来源、未决项、作者选择；每条能回到对应材料和当前版本。人修改某项解释或取舍后，相关提纲与稿件标出影响位置。概览复用 Architecture、Concept、Claim、Evidence、Source、UncertaintyItem 和 Decision，不产生第二份权威内核；概览要把分歧与未知显示出来，关系的变更回到材料和作者选择，组织形式本身不证明关系成立。模板与示例见 [知识概览模板](../04%20Templates/%E7%9F%A5%E8%AF%86%E6%A6%82%E8%A7%88%E6%A8%A1%E6%9D%BF.md)；
- 材料记录：材料可来自公开网页、经授权的本地文档及作者提供的记录。检索入口可以替换，但每条材料保留标识、版本或获取时间、支持的段落／页码／章节、对应的问题和使用限制。只取得搜索摘要时标明未核对原文，不登记为已完成事实核验；
- 交接与恢复：研究交付后暂停时，交接问题清单、材料、概览、版本与停止位置；自动化实现另记录模型、检索设置及可取得的用量信息。更换工具或恢复会话后记录当时有效的配置，不把默认配置静默当作原配置。恢复成功不等同于结果完全可复现；
- 人看得到什么：每轮研究后，人应能看到新增发现、未解决问题和下一步选择；目标明确时优先简洁、直接的支持。

短任务仍用一张工作单承载：研究问题进「中心思想」，概览进「表达结构」，材料与冲突进「依据与适用范围」，预算与停止条件进「委托范围」。

## 展开路径

触发条件命中时，按需增加下列对象；每个新增对象都要对应工作单里的某一项，并说明它要发现或处理的实际问题。

| 触发情况 | 从工作单展开出的对象或文件 |
|---|---|
| 数据、强因果判断或高影响建议 | 主张—证据台账、数据引用记录、不确定性登记 |
| 权利不明或敏感材料 | 来源与权利台账 |
| 多章节、多成果或多人依赖 | ContextPack（版本化）、WorkPacket（按任务）、架构与权威矩阵、执行进度看板 |
| 核心定义或方法变化 | 决策记录、变更影响清单、受影响成果的重检 |
| 公开发布 | QualitySLO、回归测试与发布候选记录、Release Gate 检查 |

### 展开时的检查项

原初始化十二步改写为下列检查项，展开时逐项确认，已在工作单中回答的直接引用：

1. 项目有独立目录和唯一 project_id；
2. Profile 已选择：框架或知识体系、书籍、文章、报告、系列成果；
3. 问题、受众、使用场景和预期变化已写明；
4. 质量目标 Q0–Q4 已选择；
5. 范围、不做事项、时间和资源已确定；
6. 中心命题、候选贡献和主要风险已声明；
7. 概念、主张、来源、证据、数据、权利和决策记录已建立或已指定位置；
8. 唯一权威来源和派生视图已指定；
9. 人机角色、禁止委托事项和人工核验点已定义；
10. 引用体例、版权辖区、许可策略、隐私与保密等级已选择；
11. 阶段门、权重、首轮 PDCA 和失败条件已确定；
12. README、索引、路线图、变更日志、ContextPack v1 和首个 WorkPacket 已生成（仅多单元、多人项目）。

### 进入条件

进入实质起草前，下列条件全部满足：

- Profile、Q 级和受众已选择；
- 外部发布项目至少定义 Q3 验收；
- 来源、版权、数据和 AI 使用规则已继承；
- 权威源、最终责任人和发布批准人明确；
- 至少一项读者任务、通过条件和失败条件已确定；
- 没有未说明的机密数据或权利高风险输入。

轻量入口中，这些条件由工作单的意图、依据与适用范围、委托范围、验收条件四项承载。

## ContextPack

ContextPack 是一次工作可依赖的最小权威上下文快照，至少包含：

- 项目、profile、版本和 QualityTarget；
- 问题、受众、范围、不做事项和成功变化；
- 权威对象、术语、已关闭决策和适用协议；
- 可用来源、数据、权利状态和引用规则；
- 已知争议、开放未知、红线和禁用材料；
- 上游对象版本、更新时间和包维护人。

ContextPack 必须有 `context_id` 和版本。上游权威对象变化后，旧包标为 stale；基于 stale 包生成的成果不得直接进入 ReleaseCandidate。

## WorkPacket

WorkPacket 是一次可执行、可验收的最小工作合同，至少包含：

| 字段 | 含义 |
|---|---|
| work_id / mode | 唯一标识及 Explore、Architect、Produce、Verify |
| objective | 本包要造成的可观察变化 |
| context_id | 使用的 ContextPack 版本 |
| inputs / outputs | 输入对象及必须交付的对象 |
| claims / boundaries | 允许处理的主张及适用范围 |
| sources / rights | 可用来源及权利限制 |
| quality_slo | 本包必须满足的质量服务目标 |
| tests | 完成前要通过的检查 |
| risks / forbidden | 风险、禁止行为和不得虚构内容 |
| human_decisions | 必须由人裁决的节点 |
| owner / verifier | 执行与核验责任 |
| estimate / actual | 预计与实际周期、返工和缺陷 |

## 状态与退出

`planned → ready → doing → verifying → passed / conditional / failed → closed`

- 缺 ContextPack（或工作单的依据与委托范围）、质量 SLO 或测试的包不得进入 ready；
- Do 中改变目标、范围或验收标准，必须生成修订版而非覆盖原合同；
- conditional 必须写明允许用途、限制和到期条件；
- closed 必须链接产物、测试和裁决证据。

## 粒度规则

一个 WorkPacket 应能在一个可管理周期内完成，并由单一主模式解释。若同时需要广泛研究、架构重构、长篇生产和独立核验，应拆分为有依赖关系的多个包。

## 度量

每个关闭包记录：前置等待、执行周期、核验周期、返工次数、进入缺陷、逃逸缺陷和人工裁决次数。轻量入口另记：创作、研究、必要核验与纯记录维护各自用时，以及返工原因；必要研究成本不算作表格负担。研究预算与研究结果分别记录；自动化执行时按可获取的信息报告耗时、调用次数或 token 用量。至少积累同 profile 的五个包后，才可用历史中位数给出周期区间；不足五个时只能标为初始估计。
