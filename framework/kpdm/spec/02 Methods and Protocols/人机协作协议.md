# 人机协作协议

## 总原则

人主导原创知识开发，Agent 主动辅助。Agent 是研究、结构、推演和校验的协作者，不是事实来源、权利所有者、责任主体或作者判断的替代品。人不必逐句指挥：授权范围内，Agent 可以连续研究、起草和检查；范围之外的实质决定返回人。

框架同时适用于不使用 Agent 的创作：去掉 Agent 一列，人的职责与保留结果不变。

自 0.5.0-rc.2 起，原《人机协作知识生产系统》（KPDM-PROD-01）并入本文件「四种工作模式与四类视角」。两个协议编号都保留。

## 人必须保留的责任

- 选择问题、受众、价值和质量高度；
- 提出经验和判断，选择或否决候选思想；
- 批准核心概念、主张和原创贡献；
- 接受或拒绝证据，核实引用和数据；
- 决定版权、隐私、保密和风险处置；
- 裁决冲突、例外和适用范围；
- 接受具体版本的文本，批准署名、披露和发布。

## Agent 可以主动做的事

- 检索候选来源和建立研究地图；
- 梳理材料，指出歧义，提出任务建议；
- 分类、聚类、术语和关系抽取；
- 提出候选想法、比较解释、推演反例和隐含假设；
- 生成目录与表达方案，试写，发现知识缺口；
- 在授权内连续起草、改写、压缩、翻译和多受众改写；
- 机械一致性、链接、格式和数据检查；反向审阅；
- 模拟评审者、读者或反方，但不得冒充真实外部评审或真实读者；多个模拟角色可能共用同一模型和同一批来源，必须明示模拟身份，不得当作彼此独立的专家意见。真实读者、领域复核与 Agent 反向检查分开记录。

候选想法不因由 Agent 提出而失去价值，也不因写得流畅而自动成为作者的立场。Agent 的提议保持提议身份，直到人接受具体版本。

## 创作活动的分工

| 活动 | 人的职责 | Agent 可执行的工作 | 最小保留结果 |
|---|---|---|---|
| 明确意图 | 选择问题、受众、预期变化和投入范围 | 梳理材料、指出歧义、提出任务建议 | 意图、成果类型、用途、质量目标 |
| 发展思想 | 提出经验和判断，选择追问方向及候选思想 | 从材料提出问题、查证、比较解释、追问遗漏与反例 | 研究问题、暂定主张或明确缺项、依据及人的选择 |
| 组织成果 | 修正知识概览，决定论证方向和表达重点 | 组织已知内容与分歧，修订提纲、试写、发现知识缺口 | 知识概览、表达方案、来源位置与未决问题 |
| 起草与修订 | 处理实质取舍、修正重要表达 | 在授权内连续起草、改写和检查 | 稿件、重要修改及待决问题 |
| 检查与接受 | 判断内容和风险，接受具体版本 | 核对来源、反向审阅、机械检查 | 预设条件、检查结果、失败处置、接受版本 |
| 使用与演进 | 提供实际反馈，决定修订和发布 | 分析问题、定位影响、协助修订 | 使用结果、修改范围、复核与版本记录 |

这些活动映射到下文的 Explore、Architect、Produce、Verify 四种模式和 [KPDM 生产控制层](KPDM%20%E7%94%9F%E4%BA%A7%E6%8E%A7%E5%88%B6%E5%B1%82.md) 的 G0–G7；本表是使用入口，不是另一套并列的生命周期。研究、试写和反向检查可以往返。

## 按意图选择研究方式

目标明确时，利用已有主张、材料与结构推进，只补足会影响成果的缺项。问题开放时，先形成研究问题和暂定知识概览；人可以观察进展、加入材料、否决方向或要求收敛。探索、聚焦和收敛是 Explore 与 Architect 内的工作选择，不新增生命周期阶段。

一次研究循环：

1. 根据人的目的、已有材料或相邻主题，从不同角度提出问题，并说明为什么相关；
2. 查找允许使用的材料，保留原文位置；区分资料所述、作者推断及尚无回答的问题；
3. 根据新材料追问冲突、条件或遗漏，并说明新增问题可能改变什么判断；「检索到相关材料但尚未讨论」的遗漏检查可按任务需要作为单独职责启用，由同一个 Agent 承担即可，重复或无关的扩展可以关闭；
4. 更新知识概览与问题状态，人随时修正重点；记录关键选择，不要求人逐轮批准；
5. 停止条件：到达任务覆盖目标、人要求收敛、预定预算耗尽，或连续两轮没有新增相关信息。最后一条是可调默认值，不是通用定律；预算耗尽不记作研究已充分；未解决问题保留。

人可以随时补充、纠正、缩小范围、暂停或要求收敛；下一项工作响应最新要求，已完成的材料与未知保留。研究可以只交付问题清单、带来源的概览和待决选择；只有需要表达为作品时，才据此组织文章、章节或报告，结构随发现修订。明确的短任务不强迫展开研究。知识概览的记录方式见 [上下文包与工作包协议](%E4%B8%8A%E4%B8%8B%E6%96%87%E5%8C%85%E4%B8%8E%E5%B7%A5%E4%BD%9C%E5%8C%85%E5%8D%8F%E8%AE%AE.md)「研究任务与知识概览」。

## 必须返回人的情形

下列情形 Agent 停止推进，把问题、候选和依据交给人：

1. 出现新的核心主张，或候选思想会改变成果的中心立场；
2. 作者原意在起草中发生变化，或结构调整改变了原意；
3. 适用范围实质扩大，例如从一个场景推广到一类场景；
4. 遇到未授权的风险：高风险事实、权利不明材料、敏感信息、公开指控；
5. 关键检查失败，或接受条件需要改变；
6. Agent 之间或来源之间出现无法用现有来源、验收条件和人的既有决定解决的实质分歧。

可持续执行、事后由人抽查的情形：普通措辞与格式调整、已授权范围内的材料整理与压缩、链接与一致性检查、按既定结构补写已批准的段落。

## 授权与接受记录

- 委托范围写进工作单或 WorkPacket：输入版本、任务、限制、何时返回人；
- 人的接受对应具体成果版本；未接受的提议不得写成作者立场；
- 授权只在给出的范围与会话内有效，新任务、新范围重新确认；
- 任何高风险人工裁决都必须进入工作单、WorkPacket 或 Decision，不得只存在于对话上下文。

## 四种工作模式与四类视角

| 模式 | 目的 | 允许输出 | 退出条件 |
|---|---|---|---|
| Explore | 扩展问题、来源、假设和选项空间 | 候选项、未知项、研究地图 | 关键选项与未知项已登记，不直接视为结论 |
| Architect | 确定对象、关系、主张和产品结构 | ClaimGraph、架构、权威矩阵 | 核心定义源唯一，依赖与适用范围可追踪 |
| Produce | 按已定架构生成出版单元和工具 | 草稿、图表、模板、计算结果 | 输出满足工作单或 WorkPacket 的验收条件 |
| Verify | 寻找错误、反例、漂移和权利风险 | 测试记录、缺陷、裁决建议 | 检查者未沿用起草者的未证假设 |

同一工作包一次只允许一种主模式。模式切换必须更新工作单或 WorkPacket，防止探索性语言静默进入规范文本；内部探索允许保留暂定主张，进入正式生产和发布前执行相应用途的条件。

| 视角 | 主任务 | 不得自行批准 |
|---|---|---|
| Researcher | 找来源、数据、反例和未知项 | 来源真实性、核心主张 |
| Architect | 建对象、关系、适用范围和权威结构 | 自己引入的架构例外 |
| Author | 形成适配受众的表达 | 自己的事实和权利检查 |
| Verifier | 执行一致性、证据、权利和可用性测试 | 降低已定门槛 |

视角可以由同一人或同一 Agent 分时承担，但必须使用不同工作包或明确重置上下文；Q3/Q4 的关键 Check 仍须满足独立视角要求。角色分离是认知隔离，不等于必须启动多个 Agent。

可预测性不来自更长的提示词，而来自五项控制：输入版本化、任务合同化、起草与验证分离、不确定性显式处理、周期与返工留痕。

## 禁止无复核委托

- 生成或补全引用、页码、数据和事实后直接发布；
- 判断他人作品是否可合法使用；
- 把受版权保护作品大段改写后声称原创；
- 把机密、个人或受限数据输入未经批准的系统；
- 代替人接受高影响主张、风险或最终发布；
- 隐瞒实质性 AI 生成，或让 AI 冒充人类专家、案例、评审或真实读者。

## 风险分层核验

| 风险 | AI 输出用途 | 人工核验 |
|---|---|---|
| 低 | 头脑风暴、措辞、格式 | 作者抽查 |
| 中 | 结构、摘要、比较、一般事实 | 逐项核对来源和上下文 |
| 高 | 数据、法律、医疗、财务、强因果、版权、公开指控 | 一手来源 + 领域复核 + 发布责任人批准 |

## 人机 RACI

| 活动 | 人 | AI |
|---|---|---|
| 目标与质量等级 | A/R | C |
| 检索候选来源 | A | R |
| 来源真实性核实 | A/R | C |
| 架构与反例 | A | R/C |
| 核心主张批准 | A/R | C |
| 版权与许可 | A/R | C |
| 草拟与改写 | A | R |
| 独立 Check | A/R，须含非起草视角 | 可提供辅助检查，不算唯一独立主体 |
| 最终发布 | A/R | I |

A=最终负责，R=执行，C=咨询，I=知会。

## 贡献记录

Q3/Q4 产品至少记录：工具或模型、用途、重要生成环节、人工核验方式、重大修改和未采用风险项。记录目标是责任和可复现，不要求保存所有无关对话。模板见 [人机协作记录模板](../04%20Templates/%E4%BA%BA%E6%9C%BA%E5%8D%8F%E4%BD%9C%E8%AE%B0%E5%BD%95%E6%A8%A1%E6%9D%BF.md)。

## 跨会话与协作接手

任务跨多轮会话或多个参与者时：

- 接手者先查五项：有效输入版本、当前中心主张、委托范围、未决事项、验收条件；这五项都能在工作单或 WorkPacket 里找到；研究任务另交接问题清单、材料位置、知识概览版本与停止位置；
- 仅修订提纲时复用仍有效的研究材料；上游变更时定位需要重查的部分，不重复完整研究；
- AI 从旧 ContextPack 或旧工作单产出的内容，在上游变更后必须重做影响检查；过期上下文的产出不得直接成为发布候选；
- 新会话不得默认继承上一会话的授权；发现与当前版本不一致的表述时，先核对再沿用；
- 每项成果有一个整合责任人；Agent 间冲突回到来源、验收条件和人的既有决定，无法解决的实质分歧返回人。
