# KPDM 快速入门

KPDM 帮你把一个问题、一段经验或一个还不完整的想法，发展成别人能理解、能用、能检查的知识成果：一篇文章、一份报告、一本书、一个框架。你负责选问题、定主张、做取舍、接受最终表达；Agent 可以查资料、提候选、挑毛病、起草和核对。不用 Agent 也能照做，把 Agent 那一列去掉就行。

你不需要先读完对象表或协议。先做任务，需要时再查规则。

## 一、从一句话任务开始

用自然语言说清你要做什么，例如「给团队写一篇说明为什么要先定义问题再收资料的短文」。然后回答六个问题，答不出的写「不知道」，不要硬编：

| 问题 | 你要回答的 | 对应的 Core-6 |
|---|---|---|
| 为谁解决什么问题？希望读者发生什么变化？ | 受众、问题、预期变化、内部还是公开 | 目的 |
| 我究竟提出什么？和已有认识相比贡献在哪？ | 当前主张、拟议贡献、还没想清楚的地方 | 知识内核 |
| 凭什么这样判断？什么情况下不成立？ | 来源、经验、推理、反例、未知 | 依据 |
| 读者拿到后能做什么？ | 理解、判断、学习、行动或创造中的至少一项任务 | 可用化 |
| 用什么形式？ | 文章、报告、章节、框架；读者怎么读 | 表达 |
| 怎么知道它对了？出问题怎么改？ | 谁来检查、检查什么、通过条件 | 验证与演进 |

只有影响下一步的缺项才需要现在讨论；其余保留为未知，边做边补。

两种起点都可以：**目标明确**，直接用已有主张和材料推进，只补会影响成果的缺项；**问题开放**，先让 Agent 从不同角度提出研究问题、找材料、追问冲突，形成一份带来源的知识概览（记法见 [知识概览模板](../04%20Templates/%E7%9F%A5%E8%AF%86%E6%A6%82%E8%A7%88%E6%A8%A1%E6%9D%BF.md)）。你可以随时加材料、否决方向、缩小范围或叫停。研究概览本身可以是交付物，不一定要写成文章；细节见 [人机协作协议](../02%20Methods%20and%20Protocols/%E4%BA%BA%E6%9C%BA%E5%8D%8F%E4%BD%9C%E5%8D%8F%E8%AE%AE.md)「按意图选择研究方式」。

一个走法示例（这是设计情境，不是真实案例结果）：你想写「怎样安排团队复盘」，起初只有主题和目标读者。Agent 提议分别研究复盘目标、参与者负担与后续行动，根据材料发现「频率」可能不是唯一变量，再问是否要区分不同工作类型。你否决不相关的分支，选一个待验证的解释。之后工作转为聚焦论证；那个解释仍标为你的假设，不能因为有几条来源就写成已成立的事实。若你只想了解问题，直接拿走研究概览即可。

## 二、填一张工作单

把上面的回答整理进 [轻量工作单模板](../04%20Templates/%E8%BD%BB%E9%87%8F%E5%B7%A5%E4%BD%9C%E5%8D%95%E6%A8%A1%E6%9D%BF.md) 的八项：意图、中心思想、表达结构、依据与适用范围、委托范围、验收条件、结果与修订、人的决定。前六项在动笔前写到够用就行；后两项随检查更新。已有文件直接引用，不重抄。

「委托范围」写清四件事：Agent 可以做什么、用哪个版本的输入、探索到什么程度或花多少预算就收敛、遇到什么情况要停下来问你。默认要停的情况：出现新的核心主张、你的原意被改了、适用范围被放大了、碰到权利不明或高风险的材料、关键检查没过。措辞、格式和已授权的整理不用逐句批准。

## 三、起草、检查、接受

1. 起草：你或 Agent 按工作单起草。Agent 的候选想法保持候选身份，不自动变成你的立场。
2. 检查：先看验收条件里的读者任务有没有被完成，再看来源、权利和事实。作者自检、结构检查、AI 审阅和真实读者反馈分开记录，不互相冒充。
3. 接受：你接受的是某个具体版本；接受不等于发布。要对外发布，另按 [发布前合规与完整性检查](../03%20Quality%20and%20Governance/%E5%8F%91%E5%B8%83%E5%89%8D%E5%90%88%E8%A7%84%E4%B8%8E%E5%AE%8C%E6%95%B4%E6%80%A7%E6%A3%80%E6%9F%A5.md)「轻量入口的最少检查」过一遍。

## 四、什么时候要展开

单一主旨、依赖少的任务一张工作单就够。出现下列任一情况时，按 [KPDM 生产控制层](../02%20Methods%20and%20Protocols/KPDM%20%E7%94%9F%E4%BA%A7%E6%8E%A7%E5%88%B6%E5%B1%82.md)「增加控制的触发条件」增加对应记录，不是照抄整套模板：数据或强因果判断、权利不明或敏感材料、多章节或多人依赖、核心定义变化、公开发布。

## 五、接手别人的成果，或接入已有草稿

接手时先查五项，都应该能在工作单或 WorkPacket 里找到：有效的输入版本、当前中心主张、委托范围、未决事项、验收条件。找不到的先补，不要沿用旧会话的授权和结论；上游改过的内容要重新核对，见 [人机协作协议](../02%20Methods%20and%20Protocols/%E4%BA%BA%E6%9C%BA%E5%8D%8F%E4%BD%9C%E5%8D%8F%E8%AE%AE.md)「跨会话与协作接手」。

接入一份已有草稿、旧框架或半成品时，不要从零重填：用工作单八项逐项对照，每项标「已有（引用位置）」「缺失」或「需重构」，只为缺失和需重构的部分生成修订任务。原有可用内容和来源保留。
