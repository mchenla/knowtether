# 反馈学习与版本治理

## 两类反馈

产品反馈针对具体知识产品：错误、歧义、不可用步骤、读者理解、案例结果和出版问题。它首先修改项目本身。

元框架反馈针对开发方法：缺失对象、阶段门无效、模板字段不足、检查成本过高或跨项目反复出现的失败。它进入候选模式库。

## 升级门槛

候选模式满足以下条件才升级为通用规则：

1. 至少在两个性质不同的项目中出现；
2. 对质量、效率、复现或风险控制有明确改善；
3. 没有与现有原则产生未裁决冲突；
4. 能写成可执行规则，而非项目故事；
5. 有反例、边界和回退条件。

## 版本规则

- Patch：错字、链接、表达和非语义修复；
- Minor：新增兼容对象、模板或规则；
- Major：生命周期、对象关系、状态或权威边界发生不兼容变化。

每次发布必须包含变更、迁移、废止、已知限制和下一轮验证计划。

每次 Minor 或 Major 变更必须建立 ReleaseCandidate，执行受影响 RegressionTest 和至少一个 GoldenCase。自举案例可以成为 GoldenCase，但不能计入两个异质项目的普适性门槛。

## 反馈记录字段

来源项目、触发情境、观察、影响、候选规则、证据、反例、适用边界、决定、版本和复核日期。
