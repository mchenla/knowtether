# 知识产品开发元模型（KPDM）总纲

> 宪法继承：所有实例必须遵循 [普适原则与不可妥协底线](../../01%20Foundations/%E6%99%AE%E9%80%82%E5%8E%9F%E5%88%99%E4%B8%8E%E4%B8%8D%E5%8F%AF%E5%A6%A5%E5%8D%8F%E5%BA%95%E7%BA%BF.md)；工程原则不得被解释为对真实性、权利、隐私或人类责任的例外。

## 目标

知识产品开发元模型（KPDM）把个人知识创作从“写内容”升级为“开发知识产品”。它面向人机协作的框架、知识体系、著作、出版物、文章及配套工具开发。目标成果必须同时满足：

1. 有明确问题、对象、受众和价值；
2. 概念与主张形成可解释架构；
3. 事实、推断、规范选择和原创贡献可区分；
4. 关键结论有匹配证据及适用边界；
5. 成果能被目标读者理解、使用或检验；
6. 版本、反馈和修改可追踪；
7. 同一内核可投影为知识体系、著作、出版物或文章。

## 七条原则

### P1｜问题先于内容

先冻结要解决的问题、目标读者和预期变化，再收集材料。资料数量不是进度。

### P2｜对象先于章节

先定义概念、主张、关系、方法和证据，再决定目录。章节是表达视图，不是知识本体。

### P3｜主张必须分类

重要主张标明性质：定义、事实、解释、规范选择、方法规则、预测、原创构造或边界声明。不同主张需要不同证据。

### P4｜权威来源唯一

同一核心对象只能有一个权威定义源。书稿、文章、图表和工具都是视图，不得各自重定义。

### P5｜生产与校验分离

作者自检不等于成果通过。阶段门必须有独立视角、机器检查、读者测试或现实验证中的至少一种。

### P6｜内部完成与外部声誉分离

内部可以交付“出版候选版”或“验证候选框架”，不能自行宣布“世界级权威”。声誉来自同行评审、采用、案例和时间。

### P7｜反馈必须回灌元模型

项目中的有效做法、失败模式和新对象先进入候选区，经跨项目复现后再升级为通用规则。

## 四层成果

| 层 | 产物 | 核心问题 |
|---|---|---|
| 知识内核 | 概念、主张、模型、方法、证据 | 知识本身是否成立 |
| 使用系统 | 工具、模板、流程、评估与决策规则 | 是否能被使用和复现 |
| 表达产品 | 知识体系、书、出版物、文章 | 如何适配读者和媒介 |
| 演进系统 | 版本、反馈、案例、研究与治理 | 如何持续变得更可靠 |

## 完成定义

一个知识产品只有同时通过内容正确性、结构一致性、证据充分性、读者可用性和出版质量检查，才能关闭。文字写完只代表 Do 完成。

## 不做

- 不把文件数量、字数或任务勾选率当成果质量；
- 不为显得原创而隐藏理论来源；
- 不先造品牌、认证或“官方”称谓，再补验证；
- 不把一个项目的特殊做法直接升级成普遍规律；
- 不让 AI 生成量替代作者的判断、责任和主张选择。
