# 开发生命周期与阶段门

## 八阶段

| Gate | 阶段 | 关键产物 | 通过标准 |
|---|---|---|---|
| G0 | 立项与定位 | 项目章程、ContextPack v1 | 问题、受众、范围、价值和不做事项清楚 |
| G1 | 研究与主张 | 主张—证据台账、ClaimGraph、不确定性登记 | 核心主张已分类，来源与未知项可追溯 |
| G2 | 知识架构 | 概念模型、权威矩阵、GoldenCase 设计 | 对象、关系、层级和定义源唯一 |
| G3 | 规范冻结 | 决策台账、术语和方法基线 | 核心冲突关闭；版本与兼容规则明确 |
| G4 | 内容与工具生产 | 已关闭 WorkPacket、章节、图表、模板、工具 | 按冻结架构完成，不发生静默漂移 |
| G5 | 验证 | QualitySLO、回归测试、GoldenCase、PDCA | 正确性、复现性、可用性和边界达标 |
| G6 | 出版工程 | 编辑稿、引用、索引、设计稿 | 内容、语言、法律和版式检查通过 |
| G7 | 发布与演进 | ReleaseCandidate、发布包、反馈库、路线图 | 限制披露、反馈入口、版本治理就绪 |

## 关键依赖

G1 没有主张台账，G2 就会变成凭感觉排目录；G2 没有权威矩阵，G4 会在不同章节重复定义；G5 没有冻结门槛，验证会退化为作者自我确认。

允许迭代回流，但不得假装跳过阶段门。文章可采用轻量 profile，仍必须覆盖 G0、G1、G2、G5、G6。

G0 必须执行 [实例化初始化协议](../../02%20Methods%20and%20Protocols/%E5%AE%9E%E4%BE%8B%E5%8C%96%E5%88%9D%E5%A7%8B%E5%8C%96%E5%8D%8F%E8%AE%AE.md)，选择 Q0–Q4，并建立来源、权利、数据和人机协作记录。任何外部发布项目未完成 Init Gate，不得进入 G4 内容生产。G4 的非琐碎任务必须由 [上下文包与工作包协议](../../02%20Methods%20and%20Protocols/%E4%B8%8A%E4%B8%8B%E6%96%87%E5%8C%85%E4%B8%8E%E5%B7%A5%E4%BD%9C%E5%8C%85%E5%8D%8F%E8%AE%AE.md) 控制；G5 必须检查不确定性负荷和回归结果。

## 阶段内 PDCA

1. Plan：冻结该阶段产物和通过条件；
2. Do：生产；
3. Check：独立校验；
4. Act：固化、限用或返工。

阶段门只有在 Act 关闭后通过。

## 默认权重

| Gate | 权重 |
|---|---:|
| G0 | 5% |
| G1 | 15% |
| G2 | 15% |
| G3 | 10% |
| G4 | 20% |
| G5 | 20% |
| G6 | 10% |
| G7 | 5% |

项目可在 G0 调整权重，但 Do 开始后不得为美化进度修改。
