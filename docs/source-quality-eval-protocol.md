# 路由修复后：资料问题能否进入最终判断

生成前固定任务：[四份材料包、问题身份与六项内容判据](../examples/source-quality-cases.json)。使用已发布0.6.0的提交`4b6b8809392ae44c61bdfa44e7e53dff5690ed0c`，不是上一轮路由修复前的运行代码。本轮不改提示或运行实现来追求胜出。

## 设计

工作汇报、工具书两类各有完整包和缺陷包；每项任务做两次反序重复，各比较停用、仅规范指导（lean）、规范加显式资料核算（full），共24份。固定gpt-6.1-sol、medium、禁网、新建只读项目、串行。同一任务三条件得到逐字相同资料；只有插件启停与项目evidence配置不同。两次任务文本相同，不给模型评分标准、缺陷答案或变体身份。

材料以已公开0.5.0运行记录为基础。缺陷是本次评估人为加入的扰动，不冒充新观察的公司问题或真实读者研究。完整包保留16条记录和正确口径；缺陷包删除一条章节启用记录，加入缺失核验附件、历史版本冲突、汇报增减方向写反、全面质量提升及实际账单节省的无依据断言。两文种使用同一底层资料，可以按问题类型比较，同时避免更换领域导致难度不可比。完整包用于识别无根据的报错，已有小样本或未收集读者数据等真限制不算误报。

复用已在原生UI正常审阅的隔离HOME；通过正常plugin add更新到正式发布字节，逐文件核对运行代码/规范与Git提交一致。不改信任散列、不降低沙箱、不改变日常HOME的开关。只在隔离配置切换，finally恢复。原登录仅以临时软链接使用，不复制或公开内容；结束移除软链接。遵循[宿主Hook信任机制](https://learn.chatgpt.com/docs/hooks)。

## 主要判断

缺陷分别记录三个层次：没有提到；具体定位但未处理；正确处理并进入建议/练习。泛泛说“注意资料缺失”“应核实”不算定位；提到问题却继续用错误数字支撑建议不算处理。按六项预定内容标准分别给未实现/部分/可用及原文依据，不合成总分。

1. 缺失配对：指出practical-chapter第2轮new缺失，当前CSV15条、该任务仅1个完整配对；不填零或虚构。对18.326%等不再由当前材料支持的汇总应限制或重算。
2. 缺失附件：reader-checks.csv被清单列出并被简报声称支持4位独立读者验证，但文件不存在。标为未核验，不虚构读者结果；缺证不写成读者无收益。
3. 版本冲突：brief的0.6.0与原始来源/context/index的0.5.0冲突；不把旧数据当当前新版表现。
4. 数值方向：汇报的逐对耗时/输入变化约为+25.883%/+25.703%，不是简报的负值节省；引用CSV可复核。
5. 质量过度结论：只有一次章节停止规则的局部变化，其余所列内容标准持平；开发AI评阅不能变成稳定、整体或独立读者效果。
6. 费用过度结论：缓存是累计输入子集，没有实际账单支持25%省钱。

六项内容判据另包括成品可用性：汇报能支持两个人日下的决定；章节有真实CSV练习、答案和迁移办法。问题发现不能用破坏作品用途来换。完整包中凭空宣称缺行、版本矛盾、已有附件缺失、正确数字算错等另记误报；适当保留真实未知不算误报。

## 测量与分析

报告每类/每变体/每条件的两次完整耗时、Hook与工具时长，实际注入字符、累计和末次输入/缓存token及工具次数。字符不是精确模型token；累计输入含多次请求及缓存，不是费用。工具阅读和重复核算单列，不能只报启动时间。资料准备、人工核查与编辑成本未计入，不能宣称总劳动投入降低。

记录真实回调、精确指导包、focused路由、不可变资料、停用组没有知据Hook/Skill。先生成全部输出，按中立编号和去路径文本制作评阅包，再冻结逐稿判断，最后揭示条件。开发AI同时设计材料，可能记得设计；不称独立人工或严格盲评。各组的改善、平局、退步、误报和失败均保留，不择优重跑。

两次重复只是本机描述性对照；复杂度限于本包，且多个问题共现，不能估计单一缺陷的独立因果效应。模型在停用条件也可能全部发现；这应报告为平局。只提供计算结果不等于资料语义审查，最终文字正确也不自动说明由Hook发现。代码输出的核算状态与Agent成文分开判断。

复现：`prepare_source_quality_cases.py`生成包及预定问题，`source_quality_eval.py`固定24次顺序与中立目录、校验正式运行字节、保存只读任务及回调。独立Decimal参考在`source-quality-reference.json`，不调用资料核算实现。结果出来后追加报告，不回写本文件把事后判断冒充预定标准。
