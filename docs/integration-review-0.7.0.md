## 修复的实际缺口

1. **发行包漏文件。** 原`package_release.py`只纳入Codex清单与通用组件，Claude清单、命令、Agent和模板都不在插件ZIP中。现在同一个插件包包含两宿主组件，断言清单版本与所引用文件都存在；市场包装仍只留在源码/仓库，不放入插件ZIP。
2. **无效记录被静默忽略。** 原发布检查会过滤掉无效主张/来源行，用重复来源ID覆盖前一条；有效行存在时仍可能通过。现在逐行验证对象、非空ID、唯一性及主张type，无效行以`RELEASE_SOURCE`返回失败，不会被丢弃。未实现语义主张分类器，不把任意type当作已核验事实。
3. **禁止使用与空成品。** 原规则只识别未知权利，`denied`、`prohibited`或其他`blocked-*`仍可能通过；空白成品也可能通过。现在前者规则失败返回1，后者输入错误返回2。权利状态仍依赖真实记录，不自动认定授权成立。

普通Hook的分层读取、规范选段、资料计算及语义指导没有增加新的提示层。自动写作对照因此检验实际输出与回归，而不是将新命令的存在等同于写作提升。

## 明确保留的边界

发布检查的`pass`只是五组规则满足，不表示授权发布、内容真实、独立审查或读者能用。它不核验人工标记的真伪，也不将接受记录绑定到文件内容散列。文本模式可能命中在正文中讨论的“DRAFT”或候选版本；应检查上下文，不能为通过而抹掉必要的事实或限制。代码块不扫描。未实现Office二进制格式检查。

Claude七个命令是操作指导，独立上下文的AI检查不等于独立的人类验证。反谄媚、反盲从、适用时MECE、自然表达及水印边界沿用现有要求，没有新增可保证语义正确或移除统计水印的能力。KPDM仍是0.5.0-rc.2 candidate，接受基线0.4.0 trial / conditional-pass。
