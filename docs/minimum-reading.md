# 写作前的最小规范阅读

## 0.5.0：按任务深度读取

匹配知识请求后，`UserPromptSubmit` 先按长度和任务词选择指导。它是可解释的启发式，不是理解任务难度的语义分类器，可能漏报或多读。

| 深度 | 什么时候 | 读取和交付 |
| --- | --- | --- |
| 轻量 | 简短说明、知识分享、局部改写等，未命中复杂任务条件 | 约270字符适配摘要；不打开规范，不要求再读Skill，并明确本次未读原文。 |
| 按需 | 长写作、研究综述、汇报、决策、书籍、出版等 | 校验并读取质量约束中“六项约束”“认知诚实与反迎合”；报告或书籍再加对应产品类型原文；表达任务再加语言细则。通常约2,200字符，选段多少随任务而变。 |
| 完整 | 明确要求“完整KPDM”或手动运行prepare | 使用下面的完整选段及协作适配全文；不是全部72份规范。 |

任务文本超过1,600字符或包含200字以上的长度要求，也会选择按需层；代码条件以 [routing.py](../kpdm_hooks/routing.py) 为准。请求识别仍先经过知识任务匹配。已收到足够选段时不再要求打开Skill；配套Skill改为主动展开完整工作流，不参与隐式匹配。宿主版本是否遵守该设置需实测。

这次不维护跨会话阅读缓存：每次匹配的请求重新提供相应指导，避免把旧包误说成已读。短任务不读文件；复杂任务仍有重复注入成本。资源实测见 [0.5.0对照](evaluation-0.5.0.md)。

## 完整读取与降级

0.4.0引入的完整读取路径保留。它同步读取随安装包提供的三份原文，核对 `snapshot.json` 中的 SHA-256，并返回下列完整选段：

| 来源 | 送入上下文的选段 |
| --- | --- |
| 快速入门 | 一、从一句话任务开始 |
| KPDM 质量约束 | 六项约束、模型语言指纹与文字温度、认知诚实与反迎合、状态主张与不得自证完成 |
| 人机协作协议 | 总原则、Agent 可以主动做的事、必须返回人的情形、禁止无复核委托 |

另外读取 [协作适配要求](../policy/collaboration.md) 全文。返回的内容包含文件相对位置、文件散列、选段行号与原文。框架文件按随包清单校验；适配文件只报告当前字节散列，用于定位版本。散列不是签名，不防止整个安装包与清单一起被篡改。

最多返回 18,000 字符；单个文件最多读取 100,000 字节。超限、缺失、散列不匹配或章节不存在时，返回 `READING_UNAVAILABLE`，不截断规范后仍报成功。Hook 保持提示型，不阻断操作；Agent 应披露缺项并补查，机制不强制模型这样做。

Codex 的 `additionalContextLimit: 0` 用于直接传递这份已限长内容，避免只收到预览。依据 [宿主文档](https://learn.chatgpt.com/docs/hooks)；宿主禁用、未信任、任务识别漏报或不同版本行为都可能使内容未送达。事件之外仍可能发生上下文压缩或遗忘。

需要完整工作流、现有选段不足或相关规范缺失时，运行完整插件自带入口：

```bash
python -B "<plugin-root>/hooks/entry.py" prepare --root "<project>"
```

命令只读、返回 JSON；成功退出 0，降级退出 2。路径由已安装 Skill 定位；不搜索私人资料库。独立 Python wheel 不含 CC BY 规范，`prepare` 会明确降级；完整插件 ZIP/Git 安装包含规范和适配要求。复杂/公开任务仍需按需读取完整相关规范、模板及发布检查。

## 如何解释证据

1. `prepare` 回执能证明读取了哪些字节；不是模型注意力证明。
2. 实际会话 Hook 回调包含首尾标识与原文，能证明宿主记录了送出的内容；不是模型逐条遵守证明。
3. 对原始输出逐项审阅，能描述该次采用和失败表现；不是全部规范合规认证。
4. 真实目标读者、独立领域核验与有对照的效果研究，才能回答相应的理解、事实或改进问题。

Hook 不保存阅读状态、不写项目、不读取会话全文。按需包中的协作文字是代码生成的适配摘要，单独报告内容散列；框架选段仍报告实际文件散列、行号及原文，不把适配摘要称为KPDM原文。

历史：0.4.1固定阅读包为7,104字符；0.4.0的历史测试包为5,594字符。0.5.0完整路径另含新增适配要求，不能沿用旧字符数。两者均不等于全部规范。
