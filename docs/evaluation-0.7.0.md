# 0.7.0：整合更新后，写作质量与开销怎样变化

本轮的确定改进是发行完整性与发布检查：保留其他Agent的Claude插件及五组发布规则，补齐漏打包文件，并修复六个可复现的机械误放行。**16份自动写作对照没有证明新增找错或总体内容质量优势；工具书的补测上限反而出现退步。** 本轮启用组多数运行更快、工具调用更少，但首次上下文增加，缺陷章节的累计输入也有增加。两次重复不足以承诺稳定提速。

工具书的试用设计值得警惕：

这些是具体的局部差异，不能抵消后换算成“总体提升百分比”。对“补测上限”的细化也含评阅者判断，应由独立编辑复核。四篇启用章节均未完全满足该项，不能把本次集成宣传成复杂写作已稳定改善。

## 耗时与累计输入

各格是两次运行的中位数。百分比**先逐轮配对再取中位数**，不是两组中位数之比。负数为减少，正数为增加。

| 任务资料 | 墙钟秒：停用→启用 | 配对耗时变化 | 累计输入token：停用→启用 | 配对输入变化 |
| --- | ---: | ---: | ---: | ---: |
| 汇报，完整 | 65.955→58.932 | −10.06% | 77161.5→47662.5 | −37.70% |
| 汇报，缺陷 | 61.659→59.981 | −2.10% | 77135→47742 | −37.28% |
| 章节，完整 | 66.374→58.811 | −11.44% | 78801→65184.5 | −18.75% |
| 章节，缺陷 | 71.227→69.662 | −2.19% | 85247→91915 | **+7.84%** |

不能只摘中位数：缺陷汇报两轮耗时变化为−7.83%、+3.62%，一轮更慢；缺陷章节输入变化为+19.12%、−3.43%，方向不一致。完整汇报两轮耗时−5.88%、−14.25%，完整章节−16.89%、−5.99%。所有单次及缓存子集均在结果文件，不隐藏不利轮次。

| 任务资料 | 三Hook合计毫秒：启用 | 工具次数：停用→启用 | 工具毫秒：停用→启用 |
| --- | ---: | ---: | ---: |
| 汇报，完整 | 2146 | 5.5→2 | 2992.5→1000 |
| 汇报，缺陷 | 2140 | 5.5→2 | 3174→1143 |

八次启用的三Hook合计中位数2.132秒。核算前置后工具调用减少，是与耗时/累计输入减少相符的机制线索；随机模型生成、缓存、输出长度和系统波动也会影响结果，本试验没有隔离各因素的因果贡献。

停用注入为0。启用的首次观察输入多约2395 - 2446 token，之后较少工具轮次才可能降低累计输入。累计输入含多轮请求及缓存；缓存是其中子集，不是实际费用。缺陷章节即展示了工具次数减少却累计输入增加，不能概括为“省上下文”。

与0.6.0相比，四题的UserPromptSubmit内容及核算结果[逐字一致](../examples/integration-0.7.0-context-parity.json)；SessionStart仅软件版本字符串变化且字符数相同。新Claude命令与release没有在自动任务中调用。0.6.0此前同题有启用更慢的轮次，不能用不同日期这次更快的结果计算“0.7版本优化了多少”。本轮没有新的自动提示或延迟优化机制。

## 发布检查与发行验证另算

原发布检查的六个合成反例均被复现为pass；修复后五个fail、一个输入错误。12个CLI控制样例符合预期。另将16份真实生成文本复制到独立检查目录，不建立人工核验/接受记录，均返回1，包含RELEASE_SOURCE与RELEASE_ACCEPTANCE；单次检查中位数0.172秒。[实际稿检查记录](../examples/integration-0.7.0-draft-gates.json)

这证明“没有记录时不自动标为可发布”，不证明稿件有假事实，也不是发布授权。没有为测试填入真实稿的human-verified或接受记录。合成控制明确标为测试数据。机械发布规则、AI内容评阅、人的核验和软件GitHub发行是不同事项。

Claude Code严格清单校验、Windows/Git Bash六条启动器执行通过；未登录CLI，没有Claude完整模型会话或七命令/三个Agent的端到端验证。托管审阅PR #3保留未合并，没有云上传或计费。最终回归、公开源码全新安装、ZIP及下载校验列在发行说明；不把组件启动当成宿主模型测试。

## 复现

评估工具需要克隆仓库及其Git历史、可用的同名模型，以及通过正常安装/原生审阅信任的隔离Codex HOME。运行前按Git对象校验候选运行文件；不能用日常HOME或改写信任散列代替准备。

```bash
python scripts/integration_eval.py --home <隔离HOME> --bundle <已安装候选目录> --output <新结果目录> --codex <codex可执行文件> --runtime 0f3ebce56132cd2e1b72f22b3f84d76206d5bd7c
python scripts/summarize_source_quality_eval.py <结果目录> --bundle <已安装候选目录>
```

人工式AI评阅全部`masked-review.json`并保存逐项判断/散列后，再运行`export_source_quality_eval.py`；导出器核对冻结文件，不能自动给语义质量打分。组件检查用`verify_integration.py`及`verify_release_regressions.py`。插件ZIP提供运行组件，评估脚本在Git仓库/源码包；仅有源码ZIP不足以执行Git对象校验。复现会消耗模型配额。

## 能据此作什么决定

0.7.0可作为双宿主分发与显式发布检查的整合版本；复杂写作继续按任务定向试用。**不增加自动提示，也不据本轮把插件改为所有知识任务默认采用。** 下一次若改进内容，应直接解决试验设计不封顶等具体遗漏，并在独立资料、真实读者/编辑条件下检验，不能靠增加规范后自评得分证明有效。

没有测真实目标读者、人工编辑耗时、组织回报、通用事实准确率、统计水印移除或完整Claude工作流；主机后台状态未完全控制。两次重复、同一开发AI评阅和多个同时注入的资料缺陷都限制外推。所有原稿、平局、退步及资源增加均保留。成文哈希针对统一LF换行的UTF-8文本，发行SHA256SUMS另对实际文件字节计算。KPDM仍为0.5.0-rc.2 candidate，接受基线0.4.0 trial / conditional-pass。
