# 0.5.0 分层指导与复杂写作：预定测试方案

任务、资料和标准在生成前固定：[任务](../examples/complex-work-cases.json)、[资料摘记](../examples/knowledge-work-sources.md)。固定gpt-6.1-sol、medium，禁止网页检索；材料来自真实公开研究，任务是可用于真实工作的完整初稿，不是事实已获独立核验的出版成品。

## 两项比较

- 轻任务：同一短文在停用、0.4.1旧版、0.5.0新版各运行两次，第二次采用相反顺序，共6份输出。主测耗时、实际上下文、累计及缓存输入、工具调用和过度处理，核对正常交付没有退步。
- 复杂任务：研究综述、8页管理汇报PPT内容、工具书章节各做两次新版/停用配对，顺序相反，共12份输出。主测每项任务列出的来源支持、综合论证、结论校准、可用建议与读者任务；不把标点计作内容质量收益。

总计18份有效输出。固定种子20261018随机排列任务块，串行运行；模型、材料、权限和任务文本相同。使用专用隔离CODEX_HOME，非日常配置，没有旧KPDM用户Hook或私人Skill。通过正常插件安装器在两个已冻结本地市场源间切换，安装准备耗时不计入任务用时；每次确认实际版本，再从配置切换启停并核对宿主清单和回调。

每个复杂任务的sources.md内容相同且有散列；开始和结束比较，允许读、不允许改。模型看到任务和摘记，不看到评分标准。所测是固定资料上的写作与审阅，不是完整文献检索能力；摘要、机构介绍及论文全文的可见范围均如实标注。

## 审阅和披露

最终文本先遮蔽条件标签，再由开发AI按各项标准给“满足/部分满足/失败/不适用/无法判断”及理由；冻结后才揭示条件。可能从输出推测条件，不称为独立或严格盲评。逐任务报告改善、平局与退步；不拼总质量分，不以阅读规范本身作为收益。

只就成文可用性做桌面审阅，没有真实管理者、研究者或读者验证。正面结果不能外推为普遍效果；无差异也不证明插件在所有任务都无效。输入token包含缓存和多轮请求，不能直接等同费用；耗时含宿主、工具和模型，非严格性能基准。

全部尝试保留，运行失败与内容失败分开；配额或基础设施失败只补受影响的任务，不换模型、不挑结果。公开任务、材料、判断和指标，长篇测试稿与完整会话本地留存；README若引用真实差异须对应可定位原文，若是教学示意须明确标注，不能把编写的Before/After伪装成实验。
