# 0.6.0：资料计算是否改善写作，启动优化省了多少时间

## 原因：测到的与尚属解释的

0.5.0的8次启用运行中，三个同步Hook合计耗时中位数为10.806秒，见[原始回调时长摘录](../examples/latency-0.5.0-trace.json)。这不是Python计算本身的CPU耗时。直接Python调用的本机小样本中位数约0.094秒，旧Windows包装约2.186秒；空PowerShell约1.343秒。新启动器移除嵌套PowerShell及重复解释器探测，实际宿主时长另见本轮对照。

上一轮两组还反复重读UTF-8中文资料，尝试Encoding、Format-Hex和转义输出。这说明工具读取链路给测量加入了额外工作；不能据此给所有Windows阅读估算一个固定损耗。本轮资料统一为ASCII编码的CSV与JSON，所有条件相同。

质量方面，旧任务已经给出整理后的研究摘记、明确任务和强能力基础模型，许多来源及判断标准在停用条件下也满足。通用规范与既有能力可能重复；二元“是否覆盖”标准也难以区分细节。这是对旧平局的一种解释，不是已证明的唯一原因。

所以这次改变的是可执行机制：显式资料清单、配对计算、缺失/重复/非法值检查、来源回执，以及显式页数/字符预算检查。它不是通用事实核验器；计算能否转化为更好的论证、管理决策或读者练习，仍用成文对照判断。

## 固定方法

依[预定方案](mechanism-eval-protocol.md)，两类任务各做两轮相反顺序的四条件对照：停用、0.5.0、仅运行优化的0.6.0（lean）、完整0.6.0（new），共16份有效输出。代码设计包含快启动和更短指导，但本轮两题均误入full路由，实际旧版与lean的规范正文相同。new与lean之间只差显式项目资料计算及对应产品提示。

两组真实工作材料是以前公开的0.5.0、0.4.1运行记录；不是虚构公司试点或全新外部用户研究。当前软件条件与文章所分析的历史版本分开。固定gpt-6.1-sol、medium、无网络；原始资料及本轮任务文本一致，消融只关闭项目配置中的evidence。

两个隔离HOME的49个系统Skill文件逐字相同，无其他活动Hook或私人KPDM Skill。旧、新Windows启动器分别经原生UI审阅，不改信任散列或绕过信任。按串行原计划补跑，未更换模型、任务或对照顺序。

第一份有效输出完整保留。初次记录把Windows反斜线表示的既有`.kpdm`文件误当新增文件；字节散列证明资料未变。仅修正计数，没有重写文章。另一次恢复进程未能初始化，未产生模型输出。设置阶段的一次CLI会话可能与首份停用稿计时重叠；该稿内容保留，性能分析需同时说明包含/排除它的结果，不能悄悄挑掉。

在读取本轮成文前，另发现资料生成器把0.5.0未记录的`long_dash_ranges`列填成0。工作汇报所需的耗时、输入和评阅记录不受影响，编译器为该任务声明的三个指标也不含此列。原输入和文章照旧保留，但所有条件均不得把这一列当真实格式测量或质量收益证据；后续示例生成器需更正为不提供该未测列。算术正确不能替代对输入资料的核实。

## 判断边界

按六项预定标准随机编号审阅，冻结逐稿判断后才打开映射文件。但首次阅读时，部分资料链接中的本机路径暴露了条件名；后续摘录去掉路径，已发生的泄露无法撤销。因此这是有盲化缺陷的开发AI审阅，不称为严格盲评或独立验证。来源数字另有独立Decimal配对参考，不以编译器自己的输出作唯一正确答案。不计算总体质量分，不把规范读取或格式通过直接计为内容质量收益。

只有每类两轮、且来源于本项目的写作任务。资料计算仅限声明的配对CSV及背景JSON，不能外推为所有知识写作都变好。资料整理与清单准备不在模型计时内；一次性写作不应为此强制建表。Stop只给提示，不自动续写，测试也没有增加模型复审轮次。

耗时包含宿主、同步Hook、工具和模型，输入包含缓存及多次请求；它们都不是实际费用。实际读者理解、会议决策效果、所有语法/自然文风、统计水印移除均未验证。KPDM候选及接受基线状态不变。

## 完成结果：16份，既有答案未重跑

[逐次性能、独立Decimal参考及逐项评阅](../examples/mechanism-0.6.0-results.json) · [16份完整成文](../examples/mechanism-0.6.0-answers.json)。成文只移除引用中的本机项目路径前缀，同时保留原始与公开文本SHA-256。评阅冻结摘要为`a3eddc013b10e78ffd85e32d8d6b6db80ef34eed1ae22bdbc0e03c1e7a13737f`；它是记录身份，不是质量认证。

冻结输入：[历史实验原包](../examples/mechanism-pilot-0.6.0.json)，SHA-256为`81486724e27d24889368e972c35eb02f195bfaad80038bd6363e79f266191549`，含上述未测字段错误，保留以便复现。修正后的[未来样例](../examples/mechanism-cases.json)不含汇报的未测列，不能冒充这次实际输入。运行代码为`0ec2d108c34396badaccc3cfb79fea84fb0b7470`；恢复脚本仅修路径计数与保留有效稿，不改运行机制。

### 完整耗时与Hook耗时

各格为两轮中位数；百分比下降指两条件中位数之比，并非配对百分比中位数，也不是稳定效果估计。

|任务|停用：总秒|旧0.5：总秒|运行优化lean：总秒|完整new：总秒|完整new相对旧版|
|---|---:|---:|---:|---:|---:|
|6页工作汇报|56.388|86.155|64.684|76.234|减少11.5%|
|工具书章节|68.334|82.688|78.679|67.182|减少18.8%|

三个Hook合计中位数：旧版10.523秒、lean 2.329秒、new 2.391秒，new比旧版少约77.3%。每个启用条件有4次；12次启用均记录到三个回调完成且上下文与对应代码计算逐字一致，4次停用无知据Hook或可用知据Skill。所有资料散列未变、未新增项目文件。

首份停用汇报可能受到设置会话重叠影响：保留它时汇报停用中位数56.388秒，排除它仅剩另一轮57.852秒；四份停用总中位数57.006秒，排除后57.852秒。旧版与新版比较不涉及这份停用计时。不得将排除结果当作另一个同样充分的估计。

资料计算没有稳定降低完整耗时：new相对lean，汇报中位数增加17.9%，工具书减少14.6%。工具书new两轮分别62.681、71.683秒；停用分别56.159、80.508秒，方向相反，不能把中位数接近理解成普遍无开销。

### 内容：没有发现稳定的新增优势

- 主要耗时/输入数字：所有8份汇报均正确给出四任务的配对百分比，未把缓存算成账单。汇报new两稿未重复错误的未测格式列，off、old、lean共6稿重复了它，来源忠实性记为“部分”。这暴露了资料生成错误的传播；不能据此说编译器识别了资料错误，因为该列本就不在它声明的计算范围内，且没有语义核验机制。
- 汇报决策与执行：所有条件都有具体取舍、合计两个人日的分工、复测及停止门槛；6页正文与讲述提示均满足显式预算。与上一轮不同，本轮提示已经明确字符上限，停用也全部达标；不能把达标归因于新增检查。
- 工具书：8稿均有可回到CSV的expression练习、正确核对答案、格式与内容质量的区别，以及团队试用与停止办法。new两稿更集中展示逐对百分比，其他稿展示逐对差值；两种计算都正确，未形成预定内容判据的稳定优势。
- 停用第二轮还给出有用的反事实判断：“若团队要求每次额外等待都不超过15秒，第一轮即不合格。”这说明好教学并非插件独有。各稿完整表格也使篇幅偏长，仍需要编辑压缩。

逐项判断及理由全部公开，不合成总分。未观察到稳定优势不等于已证明资料计算无用；本案的基础模型已经能正确算数，资料规模小而整齐，可能压低可观测增益。要检验更强价值，需要另行预定缺失/冲突资料与真实读者任务，不能事后改标准把本轮算成成功。

## 根据结果做的发布调整

1. 保留快速Windows启动器，作为本轮实际测到的主要工程收益；不加模型复审轮次。
2. 配对资料计算保留为显式清单启用的实验能力，不作为普遍提质承诺，不要求普通文章建表。
3. 修复full误判：旧规则`KPDM.*完整`把`.kpdm/task.json`与后文“完整稿”相连，导致两题读取全包。发布版要求明确相邻的完整框架请求，并排除资料路径。以原题调用Hook，规范提示由7460/7458字符降至1718/1672字符；这是确定性读取检查，没有给修复后额外跑写作速度或质量对照，不能套用上表收益。
4. 有清单但回答普通代码问题时，不再触发幻灯片结构检查；正常写作和显式页标题仍能检查。
5. 修正未来资料生成器：未测量不填零；原实验包、成文和错误记录保留。此处也说明，来源回执与计算正确均不足以保证源数据语义正确。

复现：用`mechanism_eval.py --cases examples/mechanism-pilot-0.6.0.json`及本轮对应旧/新代码、正常信任的隔离HOME运行；不要将修复后代码的结果和旧记录混合。`summarize_mechanism_eval.py`校验全部资料/回调/上下文；`export_mechanism_eval.py`只在逐稿评阅冻结后导出白名单字段。今后匿名包会在首次阅读前去掉路径，已泄露的本轮审阅不追认成严格盲评。
