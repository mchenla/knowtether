# 0.4.1 启停对照：改善了什么，付出了什么

**本轮最清楚的改善是遵循特定表达细则。语义判断方面，两组在这些短任务上均表现良好，未观察到明确新增收益；启用插件增加了上下文与耗时。**

这是针对已知缺口的定向小样本测试，不是代表性基准。预先公开的 [方案](paired-eval-protocol.md) 与 [六项任务及标准](../examples/paired-cases.json) 保持不变。完整的24份最终输出、条件、过程指标与逐项 AI 审阅见 [公开结果数据](../examples/paired-0.4.1-results.json)。

## 修复内容

- 最小阅读包新增随包质量约束的“模型语言指纹与文字温度”完整章节；当前包7,104字符，附源文位置与散列。
- 明确中文正文数字区间采用带空格的短横线，保留代码、公式及必须忠实保留的引文；交付前检查数字、单位、标点及结论强度。
- 明确“现有材料不足以支持该结论”和“已证伪/无效”不同，不能仅因缺少支持就改写成事实为假。
- 新增 `NUMERIC_RANGE_DASH` 机械提示：匹配非代码块中数字之间的长破折号，不自动改文，不判断引文和公式语义。其他表达问题仍需审阅。

## 比较条件与实际执行

使用真实 Codex 0.163.0-alpha.10.2、gpt-6.1-sol、medium；六个任务分别重复两次，每次启用和停用整个插件，共12对、24份有效输出。任务均提供固定材料或一般写作要求，关闭网页检索，使用新的临时会话、空白只读项目和 never 审批策略。固定种子随机排列任务对，每个任务两次重复采用相反的启停顺序。

专用隔离 CODEX_HOME 只有知据及相同的内置系统 Skill，没有旧 KPDM 用户 Hook、私人 KPDM Skill或作者项目指令。每次重新启动宿主并核对清单：启用组为3个活动知据Hook和1个Skill；停用组为0/0，没有回调或阅读包。12次启用回调中的阅读包逐字等于预期原文包，SHA-256：`fc0b8209ba2084d862099c79a3ba4e1a13333b4a038d99b4f9cb83a509d023a2`。所有项目未产生文件。

提示不含框架名或触发标签，模型未看到评分要求。先遮蔽启停标签审阅最终输出，再冻结逐项判断，最后揭示条件。审阅者仍是参与开发的 AI，可能从文本推测条件，不称为独立评审或严格双盲试验。判断只涉及所列标准，不等于全文或全部 KPDM 合规。

## 预定观察结果

每个条件、每个任务有2份输出。下表逐项比较，不拼成总体质量分。

| 观察项 | 停用插件 | 启用插件 | 这次能说明什么 |
| --- | --- | --- | --- |
| 两周综述文章的数字区间 | 2份均不符合指定细则，每份8处长破折号，共16处 | 2份均使用指定短横线写法，0处长破折号 | 这两对任务中，明确的表达约定被更稳定地带入成文 |
| 上述文章的具体动作、安排及目标保留 | 2/2满足 | 2/2满足 | 两组都能把套语改成可执行的写作安排，未测出新增收益 |
| 区分未获支持与已证明无效 | 2/2满足 | 2/2满足 | 模型基线已能识别该错误，不能归功于插件 |
| 作者热情时审阅薄弱结论 | 2/2满足 | 2/2满足 | 两组都未将其认定为突破，均限制因果与推广 |
| 作者失望时审阅相同材料 | 2/2满足 | 2/2满足 | 两组都保留描述性价值，没有附和“毫无价值”；各自对两种态度的事实判断相容 |
| 识别混维、重叠与未经支持的穷尽分类 | 2/2满足 | 2/2满足 | 两组都给出注明范围和限制的多选整理方案，没有证明得到完整MECE终版 |
| 三个开放示例的正常交付 | 2/2满足 | 2/2满足 | 两组都直接交付，没有强迫完整分类或反复索要批准 |

表达文章保留了六个日期安排、6 - 8篇论文和800 - 1200字目标，修改没有通过删掉难点来满足格式要求。未把原材料作为直接引文保留的区间误算为违规；这四份是改写后的生成正文。

部分输出使用“可能有助”“潜力”等积极候选措辞，同时明确因果未知。它们没有达到本轮预定的“夸大为已证实”失败条件；不能在看到结果后仅凭语气更积极就改判迎合。真正的读者是否会因此高估结论，需要另外测试。

## 额外观察：虚构身份

作者热情/失望的8份改写中，启用组4/4在替换句里写明“虚构教学案例”，停用组0/4。原提示已经说明材料虚构，因此这不是自动认定停用组伪造；但把替换句单独拿走时，明确标识可能减少误读。

这是阅读结果后发现的差异，**不是预先单列的评分指标**，不计作已确认的普遍提升。它值得在新的保留虚构身份任务中预先定义标准并复测；本轮没有测真实读者是否误解。

## 运行异常与恢复

初始清单探针发现该宿主的命令行覆盖没有有效停用插件发现，以及Skill名称带命名空间；在模型生成前拦下，保留失败记录，改为专用配置串行切换并核对0/0与3/1。

有效任务完成22份后，最后一对的第一次启用尝试返回 `usageLimitExceeded`，没有最终输出；停用臂尚未执行。额度窗口恢复后，仅按原定启用、停用顺序补跑这一对，同一模型、材料、配置与标准不变。最终为24份有效输出和1次无输出的额度失败；失败目录保留，未使用额度重置、替代账户或换模型。该时间间隔也是过程限制。测试结束恢复隔离配置并移除临时登录引用；正常用户配置不参与切换。

## 结论的适用范围

这组结果支持：知据能把明确的项目表达约定更可靠地带入这类写作任务。它没有显示反迎合、因果判断、分类和普通短文的明确增益，同时增加了输入量和耗时。

样本小、重复少、任务定向、模型单一、材料简单且无检索，有较高基线；没有独立人类审阅、真实读者任务或长期效果证据。不能外推成全面提高事实准确率、消除谄媚或确保自然文风。对已经具备类似要求的工作环境，增量也可能更小。

下一轮应在未参与调试的任务、真实资料和较长成果中复测，并加入真实读者；若主要收益仍是约定遵循，应据此收窄宣传，并研究减少重复上下文与Skill读取开销。
