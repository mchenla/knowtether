# 0.6.0路由修复后：缺失、冲突与错误资料的写作对照

本报告对应[生成前固定方案](source-quality-eval-protocol.md)，与[上轮修复前16稿](evaluation-0.6.0.md)分开。使用正式0.6.0提交`4b6b8809392ae44c61bdfa44e7e53dff5690ed0c`；本轮不修改运行机制。

## 材料和判断范围

两类产品是工作汇报与工具书章节；每类有完整包和人为扰动包，三条件（停用、仅规范、规范加核算），两次反序重复，共24稿。基础是已公开0.5.0的真实历史测量；扰动是测试数据，不能当作某个真实公司的缺陷或收益。所有条件看到同一材料，只有插件与evidence开关不同。缺陷答案、评分标准与变体名称不进入模型项目。

预定问题包括一条缺失启用记录、被声称支持独立读者验证的缺失附件、历史版本冲突、耗时/输入方向错误、夸大整体质量提升及缓存推导实际账单。按问题分别审阅具体定位、正确处理及进入最终决定；不把提醒出现、无依据报错或字数达标当作内容质量收益。完整材料中的真实未知仍应保留，不算误报。

运行前四份包均通过正式代码只读调用：聚焦路由；完整包章节2个完整配对，扰动包1个完整配对、另有未匹配ID；资料核算状态ready只表示其声明数据已计算，不表示所有资料完备、正确或核验通过。背景语义、未声明附件与跨文档冲突不是该算法的自动检查对象。

本次中立运行目录为S加数字；条件映射留在本地，评阅前再次随机编号并移除精确的本机项目路径前缀，保留原文及公开文本各自散列。保留数学转义等其他正文，避免脱敏顺带改文。评阅者仍是设计材料的开发AI，不称独立人工或严格盲评。

## 耗时与上下文口径

完整计时包含宿主、模型、工具与三个同步Hook。另列Hook及工具时长、注入字符、累计输入/其中缓存、首次可见请求输入和工具次数；首次可见用量不是纯Hook token。字符与精确token不能互换，累计token不是账单。资料准备、人工复核与修改工时未测，不能称总劳动节省。

每项只有两轮，材料来自本项目，且多个问题同时出现；既不能估计总体稳定效果，也不能把同一问题在重复稿出现次数当成多个独立研究。跨条件的成文差别与代码能自动检查什么分开解释。

### 完整材料揭示了一次实质性误报

完整包中，每条件也是4稿。停用及规范+核算组未见捏造的资料问题；仅规范组有1稿误报：工具书第2轮、`S024`/匿名`R11`，把`MMPMMM`的第三位P误读为第四位，声称正确简报解释有错，转而建议验证“可核对练习”。原始第三项是“可执行比较与停止规则”，第四项练习本来已满足。这不是标点差异，而是错误核对使后续验证方向偏离。

另有仅规范组缺陷工具书第1轮`S001`/`R06`的试用方案写“记录不足时延长试用”，未给批次或时间上限，该项执行性记为部分。完整材料一稿把−7.37%写成−7.36%，另作小舍入差异记录，不把约0.01百分点的差异包装为内容收益。逐稿理由均公开。

这些单次差异不足以证明规范提示导致误报，也不能据核算组没有发生同一错误，就宣称其稳定改善内容质量。当前更可靠的结论是：自动接收指导、做更多检查，仍可能把正确资料“纠正”错。

12份汇报均交付6页，独立正文/讲稿计数最大157/111字符，符合160/120预算；各组均达标，不归功于新增产品检查。工具书均有可由CSV重算的练习与答案；较长完整表格仍需编辑压缩。读者是否真正理解、能否据此作出更好决定尚未实测。

## 根据结果采取的调整

运行代码继续使用正式0.6.0，不增加规范、提示或自动复审轮次。此次更新的是公开评测材料、完整成文、能力说明与主页示例。

- 配对核算仍为显式清单启用的实验能力；把它定位为减少部分数据整理/核算工作，不宣传为已证明的通用提质或事实核验器。
- 不强制普通写作建清单；有无插件均需保留来源范围、原始值和复核办法。发现问题次数不作为成功标准，还要防止把正确资料“纠正”错。
- 目前没有证据支持靠继续堆规范解决复杂内容质量。若继续开发，宜另行预定测试结构化主张与来源逐项校验，并引入真实读者任务；本轮未实施这些新能力，也不把未来方向写成已验证成果。

资料准备、清单制作、人工复核成本未计时，后台主机负载未完全隔离；两个重复也不足以估计稳定效果。KPDM候选及接受基线、语法/自然文风/统计水印等未验证边界均不变。
