# 0.4.1 启停插件配对测试：预定方案

此方案及 [任务和逐项标准](../examples/paired-cases.json) 在运行结果产生前固定。它针对已知问题做定向试验，不作为代表性总体基准；不因后续结果不理想而替换任务。

- 六个知识写作/审阅任务：区间与自然表达、未证实与证伪、作者热情、作者失望、分类、正常开放举例。
- 每个任务重复两次，每次分别启用与停用完整插件，共12对、24次模型任务。
- 固定 gpt-6.1-sol、medium、相同原始提示与材料；关闭网页检索，使用虚构教学材料或一般写作任务，避免来源随网络变化。
- 每次使用新的临时会话与空白只读项目，审批策略 never。相同隔离 CODEX_HOME 无旧 KPDM 用户 Hook、私人规范 Skill 或作者项目指令；只安装候选 KnowTether。
- 通过每个进程的 `plugins."knowtether@knowtether".enabled=true/false` 切换完整插件。运行前分别核对 `hooks/list` 与 `skills/list`；停用组不得有活动知据 Hook、Skill 或阅读包。项目配置停用 Hook 不足以作为停用组。
- 每个任务的两次重复采用相反启停顺序；固定随机种子20261017，随机排列任务对。最多同时跑两对，各对内部依预定顺序执行。
- 同一现有登录供宿主认证；不把凭据写进结果或公共仓库。测试脚本不复制凭据、不修改信任，隔离目录由操作者先安装和审阅。

## 观察与解释

主观察：生成正文中的数字区间长破折号，以及按任务标准审阅的结论强度与材料忠实度。次观察：实际交付、有无不必要异议/审批/过程说明、长度、用时、宿主暴露时的 token 数。代码、公式、直接引文中的保留原文不算区间表达违规；缺证与证伪要按句义判断，不以“不成立”关键词直接打分。

条件标签遮蔽后按逐项标准审阅最终原文，再揭示启停条件。评分仍是参与开发的 AI 审阅，可能从文本猜到条件，不称为独立或严格双盲评估。每项记满足、部分满足、失败、未适用或无法判断，并保留理由；不给不同指标拼成总体质量分。两种作者态度还需横向核对同一条件内的事实判断是否稳定。

报告全部重复、平局、退步、失败与缺失。所有尝试保留；运行错误不算模型行为失败，也不偷偷删除或补跑到满意为止。只有隔离/协议执行失败才修复后重跑，并明确记录。另记录 Hook 送达与 Skill 可见性，不把机制执行计作语义质量提升。

12对样本无法估计普遍收益；任务、模型及研究者都单一，提示包含直接可执行要求可能造成高基线。结果可能显示规则遵循更好但语义判断无明显差异，或增加上下文和耗时。不得从没有错误推断消除问题，也不得从一次变化推断稳定因果规律。

宿主接口与设置参照 [App Server](https://learn.chatgpt.com/docs/app-server) 与 [Configuration Reference](https://learn.chatgpt.com/docs/config-file/config-reference)，实际隔离状态以运行前宿主清单和回调核对为准。复现工具：[配对运行器](../scripts/paired_codex_eval.py)。
