# Worksheet

- Task (one sentence):
- Product type: framework or knowledge system / book / article / report / series
- Version / date:
- Integration owner:
- Production status: registered | drafted | structurally-reviewed | author-accepted

| Row | What to write | May reference | Content |
|---|---|---|---|
| Intent | For whom; what problem; what output; internal or public; Q target (Q0 capture, Q1 working, Q2 professional, Q3 publishable, Q4 authority candidate) | project brief, the task as spoken | |
| Central idea | Current claim, proposed contribution, undecided points; for research tasks: research questions and `claim undecided` | claim-evidence ledger | |
| Expression | How the reader moves through the piece; for research tasks: the knowledge overview (or a link to it) | outline, draft TOC, knowledge-overview.md | |
| Grounding and scope | Sources with locators, reasoning, conflicts, counter-examples, unknowns; rights and sensitivity status | source and rights ledger, data references | |
| Mandate | What the agent may do; input versions; exploration budget or stop condition; when to return to the human | hand-over record | |
| Acceptance | Reader task; required checks; pass condition; who verifies | quality SLO | |
| Results and revisions | Checks actually run, failures, changes, still-open questions | check reports | |
| Human decisions | Accepted or returned versions, substantive trade-offs, the separate release decision | decision record | |

First six rows: good enough before drafting. Last two: updated with each check. Write `unknown` for missing information; never fill it in as fact. Write `not applicable` only with a reason.

## Expand control when

- [ ] data, strong causal claims or high-impact recommendations
- [ ] material with unclear rights or sensitive content
- [ ] many chapters, outputs or people depend on each other
- [ ] a core definition or method changes
- [ ] public release (at least Q3; run `/knowtether:release`)
